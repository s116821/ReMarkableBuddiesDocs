# Conversation management in Manager

This guide describes the implemented conversation-management slice accepted by independent source review and Windows/Linux retained-package qualification. Those checks do not establish physical tablet/native/runtime readiness or a merged-main release; final paired review, merge and publication are separate outcomes.

Both browser/local-helper and Electron companions offer a separate **Conversation management** flow over the supported ordinary schema-one producer. Read tablet state, inspect conversation IDs, then explicitly select a current ID. No first row is selected automatically. The candidate snapshot grants no eligibility or write authority.

**Inspect selected conversation** and **Prepare logical removal preview** each obtain a fresh selected-target producer read. Review the final prepared counts and deliberately **Confirm logical removal** once. Only the current conversation root and optional historical binding are logically removed. Retained history, turns, source media, export associations and native pages remain; this is no physical-space or synchronized-delete claim. Manager never stops or restarts Buddy and does not access a running Buddy admin API.

If an operation may have dispatched and its reply is uncertain, use **Check original logical removal**. It sends the same original private intent read-only, without new Apply, nonce, re-preparation, rollback or automatic retry. Historical receipt acknowledgment and current conversation state are separate: a receipt may be verified while current state has changed. Unchanged/unresolved/no receipt never proves historical no-deletion. A positively known pre-dispatch Busy/capacity refuses without fabricating a new uncertain original; genuine originals survive.

Preview stages expire after two minutes. Original Status custody lasts at most thirty minutes without renewal, with eight retained originals and thirty-two invocation entries per reference. Expiry, capacity exhaustion or host restart cannot recover or replace an original. **Show original operations on this computer** reads host memory only. Stop targets the captured local invocation; before a reference exists it detaches only the UI wait, while bounded host work may remain Busy. Old replies/cancel/timers cannot authorize another write or affect a successor.

Supported ordinary history/mode, service inactivity, strict bounds and original custody remain producer requirements. Unsupported generations, selected/sync state, unfinished/conflicted histories and large/unreadable Stores refuse without false empty data, alternate commands, repair or service mutation. Current generation4/native/Writer support remains separately owned; this consumer does not widen existing report versions.
