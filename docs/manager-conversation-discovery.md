# Conversation discovery in Manager

This guide describes the accepted source implementation in the paired Manager/Docs change. Current hosted package acceptance, coordinated delivery and publication remain pending; it is not a claim of a released or tablet-qualified flow.

Both browser/local-helper and Electron companions offer **Inspect conversation IDs** after a consistent wired tablet-state read. The explicit snapshot contains at most sixteen sorted Buddy-owned conversation root IDs and a count. It reads bounded saved Buddy records and requires the installed producer's supported ordinary layout and inactive-service custody. Inspection never stops a service, repairs storage or selects a conversation.

A complete empty result means no current supported IDs were observed, not empty storage or absent retained history. Busy, unavailable, conflict, unsupported and too-large refuse without a partial list or false zero. IDs do not establish deletion eligibility, native page links, runtime readiness or reclaimable space. There are no row actions; later management requires a separate deliberate selection and fresh inspection/preparation.

**Stop waiting for conversation IDs** clears the local wait and snapshot without canceling a remote command or releasing host ownership. The original bounded read can still finish; late results cannot refill a stopped or newer view. Connection/boot changes, explicit tablet-state reads, hiding the page and other admitted maintenance clear the snapshot. No automatic retry, polling or persistence is added.

Read the [Manager manual at the exact reviewed source](https://github.com/s116821/ReMarkableBuddiesManager/blob/94caf50e51fc8139ec9cdcbb691d77ac6dcf1a5c/docs/conversation-inventory.md) for UI behavior and the manual producer equivalent. The [consumer specification](../openspec/specs/conversation-discovery-companion/spec.md) and [active detailed contract](../openspec/changes/manage-conversation-discovery-companion/contract.md) define the strict report and shared-owner/Stop limits. The unchanged [producer specification](../openspec/specs/historical-conversation-inventory/spec.md) owns its ordinary-store/read-work/inactive-unit rules. There is no format3, selected/native, provider or runtime adoption implied by the consumer.

Controlled source/helper/browser/Electron checks remain distinct from exact retained-package and physical supported-device qualification. The same active change must complete its review, own archive and coordinated delivery; this preparation is not a standalone planning release.
