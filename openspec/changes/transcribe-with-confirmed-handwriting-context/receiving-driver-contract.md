# Local receiving comparison driver

This increment supplies a test-only driver through the existing same-Store
Writer image receiving and explicit confirmation methods. It adds no public CLI,
provider, registry or native ingress. The default controls use the synthetic
test engine. The separately admitted Barton fixture is described below.

Before any receiving operation, admit exactly one seed and one to three target
original PNGs. Reject repeated seed/target or target/target image hashes, invalid
images and an empty or oversized target set. These checks establish byte
separation only, not same-writer provenance or semantic disjointness.

Use one ordinary-local Store and its actual Ledger/Dispatch owners throughout.
Run each target once with enabled empty-profile selection, then receive the seed
once, resolving its actual NormalizedText correspondence. Exercise one distinct
caller-asserted explicit confirmation intent with frozen operation/input and
expected heads through the existing confirmation API. Do not add authentication
infrastructure or claim a synthetic fixture is a real human/native UI event.
Run each target once more with the confirmed seed selected. All receiving uses
the production normalizer/request builders and downstream Generate path. Keep
operation/source/turn identities distinct, preserve reports through output, and
do not retry failed model calls, confirmation or receiving operations.

The bound is seven Writer operations and fourteen synthetic model calls: three
empty-profile cells, one seed, three confirmed-profile cells. Fewer targets reduce
this bound. The fixed baseline-first order is a mechanics control; a later live
comparison must independently review ordering and corpus admission rather than
claim randomized or blinded efficacy from this driver. Frozen target truth must
never be a driver/request input. Synthetic replies are explicitly test data.

Focused controls cover the full six-cell path, actual normalized-source
confirmation/provenance, example presence only in normalization, stable seed
identity, duplicate/oversize refusal before calls, and first-call failure without
retry or confirmation. Existing runtime controls retain coverage for captured
ownership through errors, stale revisions and replay refusal. Passing these
controls establishes receiving mechanics, not handwriting benefit, pen input,
native confirmation, representative learning or the frozen mathematical gate.

A separately reviewed corpus must identify supported seed transcription,
caller-asserted explicit confirmation provenance, distinct same-writer pages and
evaluator-only target truth before any real-provider comparison is selected.
Missing corpus does not block this local driver. The active change remains open
for its uncompleted recognition, learning, native and coordinated delivery gates.

The separately admitted Barton qualification fixture uses this receiving driver
with a single live engine only after a manifest-bound selection. Three baseline
targets and the seed run first. The same process retains its Store and Dispatch
while it publishes actual seed normalization, image/source/turn revisions and
conversation heads, then waits at most ten minutes for a reviewed confirmation
bound to the exact published gate bytes. Missing, stale or refused review ends
the attempt before context. The source-owned intent and commit path supplies
confirmation evidence. Only a completed confirmation allows the three context
operations. A consumed attempt cannot resume after an interrupted or unknown
outcome. The fixture preserves call-start and call-return receipts, receiving
reports, normalized source records and the confirmation result separately.

The fixture caps the first stage at eight calls and the full sequence at
fourteen. Every model call uses the production request builder and the existing
single-request provider option. Frozen target PNGs are identical within each
pair. Evaluator reference text, masks and anchors stay outside the fixture
inputs. The controlled seed reading enters only the explicit confirmation
stage. A reviewed controlled confirmation is fixture provenance.

The diagnostic fixture retains exact engine-returned text up to 64 KiB before
the production parser receives it. Larger text records only its size and digest.
Per-cell evidence records the normalization or receiving stage and the existing
Writer status. An unsuccessful Writer status ends the comparison even when the
receiving function returned a report. The fixture records no transport headers,
credentials or provider error messages.

The original WholePage instruction advertised 32,768 bytes per page even for
typed receiving. The corrected instruction takes the per-page, aggregate text,
and complete JSON response byte caps from that call's existing options. Default
notebook normalization therefore advertises 32,768 / 131,072 / 131,072 bytes,
and typed receiving advertises 4,096 / 4,096 / 16,384 bytes. The prompt and
extractor revisions identify the changed instruction. Parser limits and
whole-page abstention stay the same. The consumed first baseline returned an
engine result but retained no text, so its exact refusal cause remains unknown.

WholePage requires the entire spread to be readable and treats an empty
`unreadable` response as valid abstention. The receiving fixture cannot use
that result for Generate or seed confirmation. The Barton evaluation masks
uncertain spans after receiving, while the actual spread still includes
overprint, faint ink and ambiguous suffixes. This makes the frozen corpus a
poor fit for qualifying the complete WholePage receiving chain. A valid
abstention, malformed response and downstream Writer refusal are recorded
separately.

The Lincoln physical-note fixture uses one full seed frame and one frozen target

This single case is exploratory.

### Explicit enrollment comparison after valid abstention

A separately selected fixture may proceed to a human-reviewed seed gate
after valid WholePage Unreadable. Only the seed cell in this fixture can
carry the operation-owned Writer abstention capability. Every target still
requires successful Writer receiving. The reviewed seed gate identifies
the abstention, exact image, current source and turn, and separate save
operation. Its distinct approval decision authorizes the fixture owner to
exercise typed enrollment with the bounded reviewed seed text. This is
fixture provenance. The review file supplies no native or product intent.

The post-confirmation arm starts only after observed successful publication.
It uses the same target bytes and ordinary Writer context consumer. A
malformed, unavailable, stale or unapproved result ends the comparison.
The earlier live selectors retain their legacy complete-page-only rules.
Any fresh invocation needs its own unused packet and independent review.
The maximum remains four calls before confirmation and six total for one
target. Valid seed abstention naturally uses one fewer call.
