# Design

Use current Rust publisher ff8ad75bec45fca403d55a7b6d93eb83ab732e3d release/coordinator.py contract: armv7-unknown-linux-gnueabihf and aarch64-unknown-linux-gnu reader-buddy target tar.gz files, provenance.json, annotated tag object, reader-buddy-complete record and server SHA256 asset digests. Main authorized this disjoint consumer in the existing chat; exact contract/API handoff precedes code. No serialization is invented for the signed APK producer.

Trusted input is an explicitly selected clean stable tag at fixed repository s116821/ReMarkableBuddies. GET git/ref/tags/<tag> and its annotated git/tags/<sha> object must resolve one commit. GET releases/tags/<tag> must be published stable with exact canonical HTML URL and exactly the three current assets. The completion record binds tag/version/source, package digests and provenance digest; compare it to server digests. Asset IDs determine fixed API downloads, never caller-supplied remote URL. Public requests carry no credentials; bound JSON/body sizes, deadlines, per-package/aggregate bytes and allowed HTTPS redirect hosts. Rate-limit/transport/schema failure is sanitized refusal.

Create only a NEW explicitly selected local quarantine directory after metadata validation; refuse existing directory/path alias, symlinks and source destination collisions. Fixed known asset filenames opened exclusively; stream/hash original compressed bytes while enforcing expected length/digest. No decompression/extraction, archive payload parsing, executable/script launch or package database. Read small bounded provenance bytes only; identity/digests must agree with authenticated canonical release records. Opaque archive bytes are not validated as ELF/native-safe packages.

Recheck tag and release identity/digests after download before exclusive final receipt. On interruption/refusal, incomplete quarantine remains clearly without successful receipt; no retry append or deletion of user files. Completed receipt states current legacy format, checksum agreement and APK-install eligibility false, not signature/SDK/model/firmware/payload safety or future authority. Any subsequent consumer must reverify bytes; path/content brackets are not an atomic guarantee against an out-of-contract same-user writer, especially on Windows. Host staging contains public release files, not credentials; NTFS private-key guarantees are not repurposed as binary-cache authority.

The manually selected destination is an absolute normalized new child of an existing canonical local parent. Limits are 256KiB per API JSON, 64KiB provenance, 512MiB per tarball and 768MiB aggregate assets, with five-minute total deadline and at most five redirects. Requests omit credentials; HTTPS redirects are restricted to api.github.com, github.com, release-assets.githubusercontent.com and objects.githubusercontent.com. JSON duplicate members and depth over32 refuse. Source tags must be annotated directly to a commit. Publication recheck includes tag object/commit, release ID/publication time, asset ID/name/size/digest and completion identity. Files are independently rehashed before completion. Receipt bytes are synced to .quarantine-receipt.pending then atomically linked exclusively to quarantine-receipt.json; successful publication requires local filesystem hard-link support. Pending files grant no success. No remote tag immutability or external compiler/signature claim is made.

Tests serve actual bytes via controlled local HTTP against fixed API-input translation: success, corrupted/truncated/oversized/missing assets, duplicate/wrong release/tag/record, moved tag/release, redirect refusal, cancellation and existing/symlink destination. Preserved assets must equal supplied bytes; no extraction/execution sentinel. Required cross-platform Node/host checks and public manual setup remain. Main producer serialization/signing/trust/compatibility and physical work untouched; no placeholder installer API or metadata-only eligibility.

Valid Windows test fixtures resolve their freshly created TEMP parent with realpath because the runner's environment can use short-name/case aliases; the consumer still refuses noncanonical and linked destinations. The existing shell-portable source CI block explicitly uses GitHub's bash runner on both platforms so any failed native command terminates that block; default Windows PowerShell had masked a failed npm test when subsequent commands succeeded. This narrow CI guard does not change release/version policy. Acceptance requires actual passing Node test logs as well as job conclusions. Other inherited PowerShell blocks remain separately owned audit work.
