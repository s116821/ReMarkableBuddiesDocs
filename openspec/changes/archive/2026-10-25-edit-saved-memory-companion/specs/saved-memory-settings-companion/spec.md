## ADDED Requirements

### Requirement: Shared explicit saved-memory declaration editing
Both companions SHALL inspect and deliberately save only supported memory.enabled/profile declarations through the unchanged producer contract, preserving origins, parent/no-op semantics and exact accepted profile spelling while exposing only enabled boolean and profile origin/presence.

#### Scenario: Keep, set or clear nested declarations
- **WHEN** a user begins an observed editor and explicitly saves a supported nonempty enabled/profile patch
- **THEN** only that original-bound patch is prepared and applied at most once, producer no-op performs no apply, and missing/null/empty-parent/selection constraints are preserved without profile creation, discovery or repair.

#### Scenario: Invalid or stale conditions
- **WHEN** producer validation, file/path/base/patch/target binding, current identity, expiry or public/private shape fails
- **THEN** the invocation refuses without refreshed conditions, fallback, normalization, arbitrary input echo or broader authority.

### Requirement: Private bounded replacement and original reconciliation
The consumer SHALL clear exact private replacement draft and actual DOM synchronously, retain no raw profile patch after save, and preserve only bounded original hash-only context for explicit reconciliation after possible publication.

#### Scenario: Submit or invalidate the editor
- **WHEN** saving starts or the editor is refreshed, hidden, disconnected, stopped, expired, destroyed or superseded by other maintenance
- **THEN** private draft and actual input clear before the relevant first await/event boundary and stale completion cannot refill or clear a newer editor.

#### Scenario: Possible publication or unresolved status
- **WHEN** apply may have run without a complete verified response or original desired bytes remain unresolved
- **THEN** the original opaque reference supports explicit read-only status with no profile patch, reapply, automatic retry, silent eviction or settlement by a later refusal. After an unresolved observation, cancel or failed/late status returns valid unknown/null-report fallback retaining the same original and last retained observation, without a fabricated successful read or repeated write.

### Requirement: Saved-only authority, shared custody and attributed verification
The consumer SHALL keep runtime activation unverified, preserve all existing Reader/Writer/selected-memory drafts and manual behavior, enforce six-lane ownership and complete only its own guarded independently reviewed lifecycle.

#### Scenario: Saved disable or profile replacement
- **WHEN** saved enabled/profile changes verify or desired bytes are currently observed
- **THEN** both companions state saved-only/runtime-unverified results, without claiming automatic Reader activation, profile membership, provider/native readiness, manual maintenance disablement or restart/next-request effects.

#### Scenario: Busy or stale cancellation across maintenance
- **WHEN** another model/basic/forget/export/research/memory-settings invocation owns I/O or an old callback races newer work
- **THEN** Busy performs no hook/cancel/I/O and stale cancellation/completion cannot revoke, release, clear or settle the unrelated owner.

#### Scenario: Historical inputs and complete linked delivery
- **WHEN** the consumer is proposed for delivery
- **THEN** original90reports/160hashes and capture provenance remain unchanged, new synthetic transport/UI evidence is separate, ordinary both-OS source/retained checks and independent review precede own canonical sync/archive and final composed Docs-first delivery, with actual publication and broader qualification tracked separately.
