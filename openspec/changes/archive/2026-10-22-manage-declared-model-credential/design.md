# Design

## Fixed existing reference and ownership
Use only the explicit existing configuration's validated `model_credential` name and `paths.credentials` root. No reference or caller path is accepted in requests. Preserve existing CLI > environment > protected-reference resolution. Inspect/prepare/status intentionally examine only that declared credential, not the environment or any other credential, and do not initialize a Store. Apply alone acquires existing selected-aware Store ownership and current ordinary/selected unconfigured/local/shared/isolated configuration custody. No domain membership follows.

This producer is Linux-qualified using Unix filesystem semantics: regular files/private owner permissions, stable inode/device/owner metadata, hardlink count and directory durability are required. Other targets (including other Unix hosts) report unsupported before credential-file access or publication; they are not given an unverified permission fallback. Both Manager distributions may later consume the same tablet-side command; this is not desktop-only product functionality. Unix actual CLI evidence must run in hosted Linux. Non-Linux compile/unsupported tests are distinct from Unix credential execution.

## Confidential evidence
Original/target SHA256 values of secret contents are sensitive offline-comparison material. They and all reference/path/metadata bindings stay in confidential CLI transport/host memory; never call them nonsecret or expose them in public UI, errors or logs. An independent public view may show only status/presence/action/disk-readback/runtime-unverified. No complete future host API is authorized here. No secret byte or arbitrary existing text is emitted, including refusals. Status needs confidential original intent, not raw secret text. Public fixtures contain only explicitly synthetic credentials; real intents must not be committed or used as diagnostics.

## One owned conditional writer
Reuse the Store mutex/current custody and filesystem protection/sync patterns; add only a narrow credential-file writer rather than invoking `replace_config_document` on a different file or rewriting Config. Recheck original Config bytes, exact resolved path/root identity, parent identity/private permissions, file absence or exact bytes plus metadata under the same Store mutex before publication. All Buddy credential mutations must use this writer. This is cooperative owned-root exclusion, not a claim to serialize hostile same-user external filesystem mutations. Changes observed before the conditional boundary refuse; no fallback, refresh or chmod repair.

Install seals/fsyncs a private exclusive sibling stage, then publishes without replacing an existing destination (a no-clobber hard-link publication followed by removing only the owned stage is eligible). A race-created destination must survive; ordinary rename-overwrite is forbidden for install. Replacement seals the sibling with the original exact permitted mode before atomic rename. Removal unlinks only the original admitted regular file. Directory sync and exact resulting absence/bytes/permissions are required for verified output. Preserve unrelated files and roots. Staging cleanup may remove only this attempt's checked owned sibling, never the destination or arbitrary leftovers.

Known pre-publication failure reports not-dispatched. Once the destination-link/rename/unlink syscall is attempted, any failure, sync/readback uncertainty, cancellation or missing/truncated report remains unknown; no rollback, second report or automatic mutation replay. Current Store/mode custody stays through one consuming report. Explicit status observes current desired file/absence under original Config/root conditions, not the original publisher, historical removal or running credential state. A different or uninspectable state cannot settle the old invocation.
