# Decisions and risks

Use the existing fixed producer command and existing Store export writer. The Manager coordinates one explicit preview and one original confirmation; it neither copies archive bytes nor writes backup.json. Never interpolate destination into SSH/shell arguments.

Use a separate optional ordinaryExport API and reduced exact safe projection, preserving old API caps. Destination is sensitive input, kept separately from signal/state, cleared in actual DOM before prepare's first await and on every editor lifecycle boundary. Ready original destination+intent lives at most120seconds; at most8uncertain originals survive renderer reload in the current host process. Terminal verified/observed outcomes release them; unresolved refuses automatic eviction/retry. No process-restart recovery claim.

Shared MaintenanceIO extends explicit ownership to export, model, basic and forget. Acquired remote work invalidates all other idle grants; busy invokes no hook/cancel/I/O. Old cancel/status/completion must match lane/reference/token/generation through final publication. Preserve original observer receiver and all existing independent readers.

Preview must state that configuration snapshot can contain private opaque fields, media may intentionally be omitted, and archive remains on this tablet. It is not device-loss protection. Restoring, copying off-device and cloud backup require separate contracts.

Confirm is a separate deliberate gesture using the exact ready original, never fresh conditions. Missing/truncated/late apply remains unknown; not-published may leave partial output. Explicit status verifies original complete destination closure and has no publisher/history authority. Ready expiry and total phase budget are checked before dispatch and after all awaits/parsing; Stop never retries or deletes partial files.

Historical Windows fixture paths are not valid tablet path authority. Parse every original stream unchanged, reject original incompatible path bindings under actual host validators, and label synthetic POSIX success/loss surroundings separately. A synthetic apply loss is not an actual induced producer transport fault.

The exact finite projection, phase matrix and path/request bounds are in contract.md. There is no diagnostic dismissal/eviction API: explicit successful original status settles capacity; host restart loses in-memory references without proving disk outcome. Identity/host replacement invalidates renderer readiness and never automatically statuses/reapplies. Worst-case control-character paths may exceed serialized JSON caps even below4096raw bytes and must refuse before dispatch; bounds never truncate. No implicit automatic status or changing an unresolved original to a current unrelated operation.
