# Design

## Preserve declarations using the same writer
Keep strict typed Config parsing plus recursive duplicate detection and pure value checks. Explicitly require object shapes at the Config root and present paths/memory/sync/personalization/non-null memory.selection records. Serde struct-sequence acceptance is not a declaration map. Request/intent/change record positions also require objects. Collection arrays such as sync.namespaces remain supported. Apply this narrow shape check to the shared maintenance parser/general inspection only; preserve its public wire and leave legacy runtime Config::load alone. Retain the validated raw JSON document and change only the explicitly selected root fields. Clear removes that key; it does not write null. Every other JSON value, omitted declaration and explicit null survives unchanged semantically, including exact decoded multiline personalization bytes and private settings. Object order/JSON whitespace/escaping may normalize on a real edit. A logical no-op preserves the original file bytes and performs no write.

The producer owns a deterministic target byte recipe: recursively sort all object keys by Rust string order, serialize compact UTF8 JSON with no trailing newline. Do not depend on serde_json Map feature-unification ordering. Hash exactly those target bytes. Reject a target exceeding the existing1MiB config limit; no truncation or normalization of private text values.

Factor a thin declaration-preserving entrypoint into the SAME existing Store.replace_config atomic publication implementation. Existing typed callers retain their contract. No second writer, journal, database or raw arbitrary-config write API. The new entrypoint requires bounded strict validated Config bytes, unchanged declared owned roots and the original whole-file hash, with the existing exclusive Store lease and inner mutex through final compare/publication/readback.

## Selected-aware write admission
Add an explicitly scoped configuration-maintenance admission reusing selected-aware existing-store validation, rather than weakening ordinary open_existing. No initialization, repair, restore, selection activation or fallback. Apply validates current ownership/generation and obtains current supported-mode custody (unconfigured/local/shared/isolated without changing it). Current-mode custody lasts through write/readback and the consuming report or failure release. Active owner is Busy. Unknown/corrupt/incomplete selected state refuses. Prepare/status are saved-file reads, not Store or mode authority; an intent binds the config path/bytes, not an assertion that a historical Store actor/group is still current.

## Why internal preview exists
The existing general view intentionally strips/discards its private hash and grants no edit authority. New explicit editor inspection creates its own host-owned revision context. Save first asks the producer to prepare an exact target digest from the ORIGINAL context and patch; it never silently refreshes the base. The host privately retains that immutable packet before its single apply dispatch. This enables read-only exact desired-file reconciliation after a lost reply without exposing full private Config or adding persistent receipt machinery. It is internal work under one Save, not another user confirmation.

Reconciliation can establish that the complete desired file is currently observed. It cannot prove which process published it, historical operation identity, runtime activation or that a failed write rolled back. Nonmatching/current-base bytes leave the original attempt unknown. A fresh explicitly requested edit is a distinct intent with a fresh observed revision, never automatic replay of the old patch.

## Shared host lifetime and UX
Use narrow identity-only editor inspection, opaque edit reference plus exact three-key patch for Save, and opaque reference for explicit status. Private base/path/target hashes and intent never enter HTTP/IPC/public state. Preserve current saved-configuration inspection unchanged. Reuse existing host/private-custody and queued-cancel patterns, with before-I/O forget invalidation and after-await generation checks. Do not replace the observer receiver or make internal run cancellation a second external event.

Ready edits invalidate on refresh/navigation/other maintenance/identity change. Possibly dispatched apply retains original packet and unknown status; later status-command failures cannot settle it. No persistence or automatic reapply after host restart. Consumer precode must concretize bounded retention and original-versus-later invocation results before API/code. UI has current saved values/origins, no-saved-override choices, one Save, neutral pending text, Cancel, and explicit status only when needed. No automatic checking loop, provider test, service button or technical hash/packet display.
