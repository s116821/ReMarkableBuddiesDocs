## Concrete integration changes

The storage module exports preserve inspection, current maintenance and the Unix
lease fixtures. The entry point retains inspection before dotenv, model,
credentials, Store, sync or device initialization, and retains the current
prepared-export and personalization one-shot routes unchanged afterward.

Inspection now explicitly conflicts with both other one-shot selectors. Without
that integration, combining the old inspector selector with a new export or
personalization selector could silently dispatch whichever route appeared first
in main. The new actual-process regression covers both argument orders for both
combinations: parse refusal, no report on stdout and unchanged fixture bytes.
Existing inspection overrides and supported logging behavior remain unchanged.
No inspector report, limits, category accounting, filesystem ownership/lock
protocol, credential resolution or normal Reader behavior changes.

The canonical platform runtime combines the inspection route with current
personalization/startup and release-metadata requirements. Its exhaustive flag
list includes the already implemented export selector as well as inspection;
the three one-shot selectors are mutually exclusive. Original archived
requirements and the canonical owned-data capability remain unchanged.
