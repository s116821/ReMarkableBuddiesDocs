## Why
The delivered fixed-reference protected model-credential producer has no Manager consumer. The separately delivered saved-reference editor does not install, replace or remove its selected file. Both browser and Electron need a deliberate file-only workflow with a stronger private reduction/lifetime boundary because even secret-derived fingerprints are confidential.

## What Changes
- Add optional modelCredential capability and one shared install/replace/remove editor for the already declared protected file; public results expose only opaque control metadata, presence and fixed statuses.
- Preserve exact accepted UTF8 including CRLF/trailing/control bytes, original conditional publication and read-only status, while excluding secret-derived binding/intent/fingerprint material from safe outputs.
- Bound private draft/packet/intent lifetime, keep unresolved original diagnostics across reference/config changes, and compose eight actual maintenance operations/all56 directed pairs.

## Capabilities
### New Capabilities
- `protected-model-credential-companion`: bounded shared protected-file editor, confidential transport/reduction and original-only reconciliation.
### Modified Capabilities
None. Existing producer, reference editor, resolver/precedence and seven delivered operation wires remain unchanged.

## Impact
Additive Manager dedicated protocol/coordinator/fixed wired transport, guarded HTTP/main-frame IPC, shared UI/manual and existing pipeline controls after independent exact precode acceptance. Central Docs owns this full proposal→implementation→verification→sync/archive paired delivery, not a planning-only merge. No credential vault, discovery, reference/file transaction, provider validation, runtime reload, dependency/version source/release infrastructure or tablet operation.
