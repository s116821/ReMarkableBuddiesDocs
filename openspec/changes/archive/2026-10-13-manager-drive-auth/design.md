# Context
Current REM42 owns cloud login/re-auth/revocation and UI. Main Drive source7987 uses drive.appdata, client/account binding and protected tokens; app/account discovery is absent. The Manager may authenticate its host while no tablet exists. Collection/group admission and tablet transfer are separate unfinished contracts.

# Goals / Non-Goals
Deliver explicit usable host sign-in/state/cancel/disconnect/revoke in both distributions. Preserve confidential host tokens and actual provider identity. No personal Google login during tests, Drive object listing/publication/delete, second sync engine, backup/restore qualification, tablet configuration/credentials transfer, native operation or production client provisioning.

# Decisions
1. Configure a Google desktop OAuth registration in a protected host file, outside source. Reuse official google-auth-library (supported Node24.21) for S256 PKCE/auth-code/refresh/revocation; pin/audit the dependency and retain notices. Consent always opens the external system browser, never Electron webContents. No embedded login/password fields or renderer-supplied client/path/endpoints.
2. Each explicit sign-in creates a fresh random state/verifier, a127.0.0.1 ephemeral-port listener, exact redirect and five-minute interactive TTL. Strict bounded GET callback, exact Host/path, duplicate/unknown argument checks, timing-safe state, one consumption and code bounds. Wrong/stale callbacks cannot replace credentials. Token/token-info/about reads15s each, no retries/redirects and64KiB bounded JSON. Production endpoints fixed to accounts.google.com/oauth2.googleapis.com/www.googleapis.com; tests inject owned localhost at the trusted host boundary only.
3. Request drive.appdata/offline consent with account selection. Confirm actual token-info audience/scopes/expiry and actual about.user.permissionId plus bounded account label from GET about?fields=user(permissionId,emailAddress,displayName). App data scope covers about.get. Host credential identity binds client ID and observed account, never a caller label. Do not fabricate collection UUID or output a ready tablet credential: no domain/backup access until separate admission.
4. Maintain single serialized host mutations and a generation/AbortController for pending authorization/checks. Cancel closes the listener/invalidates in-flight completion. Re-auth preserves previous stored grant until full new account verification and protected commit succeed; stale results never resurrect after cancel/disconnect/revoke. Re-read configured client identity before persistence. Report cached/stale vs freshly checked connection honestly; restart metadata is not current provider proof.
5. Revocation confirmation carries only the host-issued current grant snapshot ID; a changed client/account/grant refuses before provider traffic. The final live generation is checked immediately before a bounded synchronous protected save; no host cancellation event interleaves before its atomic commit. Cancellation after commit does not implicitly disconnect/revoke. An unknown child completion is reported unavailable and needs fresh custody readback. Tokens stay in owner-only host storage at fixed filenames under a protected configured host root. Python3.12 standard POSIX ownership/mode checks or maintained pywin32312 NTFS owner/explicit protected DACL creation/read checks; regular nonlink/reparse ancestors/handles, bounded JSON, exclusive new staging/atomic replace and fresh guard. No privilege takeover or permission widening, token argv/logging/renderer/localStorage. Unavailable custody fails closed; synthetic host fixtures test files and secrecy, Windows actual ACL controls remain distinct from physical USB.
6. Browser helper reuses exact loopback origin, HttpOnly session and fixed authenticated POST actions. Electron uses exact main-frame caller with fixed actions (revocation alone carries one host-issued opaque grant snapshot ID). Begin returns only a bounded consent URL/status (public state/challenge; no verifier/code/token) to open in the external browser; follow-up status exposes only enum/account/checked-time/error code. No arbitrary URL/command/file API. Old adapters yield unavailable gracefully. Shutdown cancels flow/owned resources.
7. Local disconnect removes only this Manager's grant. A host-issued opaque authorizationId binds the confirmation to the current protected client/grant digest, so changed-account/client/grant revocation refuses before provider traffic. Explicit revocation calls the maintained library/provider endpoint, previews impact on the configured app's Google grant/other clients, and reports network denial/uncertain outcome without claiming success. Never silently revoke during replacement, cloud inspection or device disconnection. Backup data/files and tablet credentials are not removed by this slice.
8. Shared responsive Tailwind view supports unconfigured/disconnected/connecting/cached/connected/auth-failed/unavailable, explicit sign-in/check/cancel/disconnect/revoke and truthful backup-not-ready state. Provider auth is independent of USB identity. No false backup state, hidden runtime approval or user-visible protocol internals.

# Risks / Trade-offs
Google app registration/consent/provider policy is an explicit deployment prerequisite; owned protocol fixtures do not certify live OAuth or cloud backup compatibility. Host protected-file custody is not whole-disk encryption. Same OAuth app/account ownership is needed for appDataFolder; credentials are not arbitrary permission to reinterpret other namespaces. Revocation can affect other grants for the app, so product confirmation explains that real impact. Existing unmerged parent reconciliation and physical/backend gates remain integration prerequisites, not blockers to independent development.
