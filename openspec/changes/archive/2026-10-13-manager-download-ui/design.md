# Design
Use accepted Manager f7c3a357 with existing quarantineManagerRelease and bounded Python verifier unchanged. A host instance owns at most one active download; renderer accepts only exact action/tag inputs, never paths/URLs/repos/interpreters. Host configuration supplies existing canonical absolute downloads parent and trusted absolute Python3.12; unconfigured refuses before traffic. Every attempt uses a random new child. The consumer retains its five-minute network/byte/process/publication/digest/atomic receipt limits; no second downloader or checksum authority.

Status/start/cancel reuse browser origin/Host/HttpOnly-session and Electron exact main-frame guards. Start returns bounded sanitized state immediately; status polls owned state, cancel targets that host operation. Concurrent start refuses; closing host aborts pending work. Completion is committed only if consumer returns an actual valid Manager receipt; late cancellation does not undo a completed atomic receipt. Failure may leave partial public bytes; never delete/reuse arbitrary directories.

UI shared controller hides stale or malformed responses and polls only active operations, with explicit cancellation/unknown host state. Display verified downloaded tag/source and host-chosen folder basename, without inferring newest/upgrade ordering, trusted signature, payload safety or update eligibility. Download all existing publisher assets to preserve the exact consumer contract. This is host storage, not a browser standalone download API; deployed sites without helper remain unavailable.

Packaging includes fixed scripts/verify-manager-bundle.py and unchanged release policy.py/coordinator.py beside existing host resources. Existing hash pins remain enforced. Tests distinguish actual controlled HTTP/ZIP/process/file receipts, synthetic shared UI, and live official/native qualification (not performed). Main publisher/backend/native ownership untouched; paired PRs and exact review/checks precede own sync/archive.

Review refinement: preserve one current-operation Cancel across an in-flight poll and drain it before scheduling another poll. Acknowledge pending cancellation without fabricating host completion; keep operation identity and successful receipt precedence.
