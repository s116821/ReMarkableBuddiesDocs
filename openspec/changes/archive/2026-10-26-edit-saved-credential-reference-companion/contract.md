## Exact public capability
Add optional `credentialReference(request)` to both hosts, HTTP POST `/manager-credential-reference`, IPC `manager:credentialReference`, lane `credential-reference`. Request is one exact object:
- `{action:"retained"}`;
- `{action:"cancel",reference:REF}`;
- `{action:"begin",connection_id:CONNECTION,boot_id:BOOT}`;
- `{action:"save",connection_id:CONNECTION,boot_id:BOOT,reference:REF,change:CHANGE}`;
- `{action:"status",connection_id:CONNECTION,boot_id:BOOT,reference:REF}`.

REF is opaque lowercase64hex, never a path or intent. Connection/boot syntax and observation validation reuse existing strict admission. CHANGE is exactly `{action:"set",value:NAME}` or `{action:"clear"}`; NAME is1..80 ASCII letters/digits/hyphen/underscore, preserving exact decoded case/spelling. No trim/normalization/coercion/set-null/unknown fields/arrays/duplicate members. Keep is local UI state and dispatches nothing. Missing clear and same decoded name skip apply only on the producer's original-bound no-change report; declared-null clear is a changed target.

Result is exactly `{contract_version:1,status,observation,credential_reference:{state,reference,current,report,retained}}` using existing observation envelope. Public JSON cap8192 bytes; request cap16384. `current` is null or exactly `{model_credential:{origin:"default"|"declared-null"|"declared",present:BOOLEAN}}`: default/null require false, declared requires true. No name, path, hash, intent, changes, arbitrary text/error or credential bytes appear in any result.

`report` is null or exactly the sanitized five producer fields `{operation,status,outcome,disk_readback_verified,runtime_activation}`; no report_version/data/raw output. Operations inspect/prepare/apply/status, statuses/outcomes and disk flag combinations must match the exact producer tables. Runtime is always `unverified`, including verified apply. States are `none|ready|invalidated|unsupported|unavailable|busy|capacity|not-dispatched|no-change|verified|unknown|unresolved|desired-file-observed`. `retained` is at most8 exact `{reference,connection_id,boot_id,state:"unknown"|"unresolved"}` records, with no silent eviction.

Ready requires same observed identity, successful inspect/read-only report/current, fresh opaque reference and a two-minute lifetime. Verified/no-change/desired-file-observed require current and their corresponding successful report/operation/disk flags. Successful status/unresolved requires its actual successful status report with null current; it cannot be fabricated by cancellation/failure. Unknown fallback has null current/report; the retained list may still say unresolved. Invalidated/none/capacity have null reference/current; failed Begin may have null reference, while status/cancel refusal keeps its requested original reference. Busy/refusal cannot grant ready/current state. Results are checked against request action/reference/identity and final host generation before publication; late replies cannot expose old ready/verified views.

## Host lifecycle and custody
Begin inspects the fixed Config only, validates strict report/path digest before admitting ready, and never changes configuration. Save clones/validates exact private CHANGE, clears all mutable draft/actual input before first await, prepares once against original file/path hashes, then applies at most once within the same aggregate13000ms budget and ready lifetime. Each child receives min(12000ms, remaining budget); no late prepare may authorize apply. Producer validation owns complete Config/target constraints, current Store-mode custody and no-op. Verify operation UUID, base/path/change/target hashes and predicted after origin/presence before dispatch. Input parsing/shape/path failures before possible dispatch are not-dispatched; unsupported/missing support refuses without old-editor fallback.

Before possible apply retain exact original prepare bytes and SHA, original identity/reference, after origin/presence and hash-only status input/intent (verified unchanged before use). Retain no raw name/change. Zero mutable input/output buffers after use, drop raw/base64/request references promptly, and never log payloads. Capacity8 refuses a ninth possible original before prepare/apply; never evict older unknowns. No automatic retry/refresh/reprepare/rebase/rollback.

Pure Status sends only the original intent and compares original desired full Config bytes. Desired-file-observed may settle this reference record only; it proves neither historical authorship nor file/auth/runtime readiness. Later conflict/unavailable/unsupported/busy cannot settle uncertainty. After unresolved, idle cancel or failed/late status returns current unknown/null-report while retaining exact original and last unresolved observation. Targeted Stop owns only its exact token/reference; Stop before a public handle is local and never falls back to global cancellation. Host-process restart can lose records; renderer reload merely reads retained records, dispatching no status/apply.
