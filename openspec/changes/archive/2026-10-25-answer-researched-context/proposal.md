## Why
The declared source/memory/research stages and explicit web acquisition exist, but
FrozenResearchContext has no production answering consumer. The live image-based
workflow does not supply this composed history/evidence to a receiving buddy.
Consuming that context is an unfinished requirement, separate from native wiring.

## What Changes
- Add an explicitly invoked receiving-buddy answer function using the existing
  frozen context and caller-selected LLMEngine without changing either interface.
- Preserve exact request/history/evidence as a separate text content part, with
  stable answering instructions, bounded strict output and captured citation IDs.
- Own temporary engine content and qualify an actual maintained caller through
  existing-engine HTTP plus representative bounded hosted answering.

## Scope
Ordinary backend model consumption only. No router rewriting, selected admission,
workflow activation, native/device access, durable answer publication, new model
settings or dependency/SDK/CI changes. Held selected/memory/cancellation lanes and
Manager retain their owners. This does not complete installed Reader or the MVP.
