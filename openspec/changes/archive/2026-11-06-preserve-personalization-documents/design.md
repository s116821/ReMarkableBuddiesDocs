## Actual gap
personalization::run currently parses a typed Config, modifies its Personalization and calls Store::open_existing then replace_config. The ordinary existing constructor preserves format1 only, refusing ready notebook4 and legacy2/3. Config's derived Serialize emits unrelated defaults/null fields that were absent in the saved raw document. Typed values can remain equivalent while declaration shape changes. This is a source-grounded declaration/admission finding, not a newly executed corruption or duplicate-key acceptance claim.

## Small raw-document target
Reuse config::inspection::document for complete typed validation plus recursive duplicate-free raw JSON, retaining original bytes/digest and Config validation. Keep current explicit existing source selection, load-before-mutation-input ordering, bounded stdin and sanitized failure categories. Inspect remains file-only and does not open Store or read stdin.

Compute the Personalization candidate using the exact existing Set/Disable/Clear semantics. Set constructs schema_version1/enabled/text; Disable sets enabled=false while retaining exact text/schema; Clear uses full default disabled/empty Personalization. Replace only the root personalization member with serde_json::to_value(candidate). All other raw root values, nested shapes, omissions and supported null declarations are unchanged. The selected parent intentionally becomes the complete existing Personalization value; this does not promise to preserve its formerly omitted children. Serialize the bounded complete raw target and validate it through the same whole-document validator before publication. This preserves JSON declaration values, not physical whitespace/member order/escape spelling.

## One scoped custody, unchanged families
Add open_existing_for_personalization (or equally explicit private name) calling the existing common admission with selected_aware=false and notebook Preferences policy. This keeps legacy format1 behavior and legacy2/3 refusal, while reusing the complete ready-notebook4 gate: original owned roots/current/actor, strict readiness/contract/capabilities, definite absent/empty selected+history directories, full recovery/all local manifests and validated absent/LocalOnly mode. No outside format probe, Unsupported fallback, second Store, initialization/adoption/repair or stage deletion. Generic config and product/research constructors keep their own behavior.

The local Store remains uniquely owned through conditional publication and exact readback, as in the existing personalization operation. No domain/provider/native client is created. Use replace_config_document with the original whole-file expected digest; retain its path/root/CAS and bounded exact-byte readback. Keep the final full reload/setting/digest verification before a successful report. Conflicts and possible publication failures keep current fixed statuses; failure is not rollback evidence. No automatic retry or replacement report is introduced.

## Public compatibility and limits
Keep Personalization, Operation, Status and public Report fields/methods and all v1 JSON shapes unchanged. Report::write_to(&self) remains non-consuming write_all without flush and carries no Store custody. The original lease ends after operation/readback, before report output; the result is historical diagnostic data, not a current lock/activation receipt. Do not silently strengthen this into the newer product/research report-held custody model or add a private field that breaks public Report construction. Output errors cannot trigger another publication. Successful mutation remains restart-required; inspection unverified. Explicit editor reports may contain selected personalization text; routine Debug/errors must remain redacted. No running reload, prompt semantics, provider behavior or Manager active-state claim.

## Meaningful qualification
Use real committed legacy1/notebook4 records and media; prepare notebooks explicitly and inventory all owned roots after preparation. Exercise Set/Disable/Clear with absent/sparse/null unrelated declarations, nested memory/Reader/product/research siblings, exact CRLF/multilingual/emoji/whitespace and16KiB UTF8 boundaries. Compare whole raw sibling values and omitted keys, exact readback, retained data/markers/current/media and old immutable snapshots. Existing typed behavior and v1 report shape must match.

Require Busy/stale CAS, invalid path/input/source, missing/foreign/incomplete readiness, corrupt history/mode, selected/retained residue and nonordinary notebook mode refusal with unchanged files. Prove legacy2/3 and excluded caller refusals remain. Use current ConfigFault before/after publication/readback controls; retain Failed/uncertainty without rollback/retry. Output prefix/immediate failure must not call the publisher again; do not assert nonexistent output-held custody or flush. Both supported hosts need actual CLI entry-point controls; Unix link/FIFO controls remain separately attributed. Current exact-head normal CI and independent implementation review precede canonical sync/archive. No model-facing change means no new live-provider experiment; no tablet/runtime test is selected.
