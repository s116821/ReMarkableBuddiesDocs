# Inspect and export historical Buddy archives in both companions

## Why
The existing selected-history archive producer is delivered, but neither companion exposes its complete read-only archive inspection or new-destination export. Users need a deliberate backup flow that preserves source history and explains uncertainty without implying that selected restore or cloud synchronization exists.

## What changes
- Shared whole-archive inspection and selected-history export with a separate policy-only consequence preview and deliberate once-only confirmation.
- Fixed wired helper/HTTP/IPC surfaces, protected path handling, finite original destination custody, original-only read-only checks and shared maintenance ownership.
- Plain primary content/media/settings consequences, optional technical counts, public manual and complete literal protocol/lifecycle/host coverage.

## Scope and non-goals
This is one paired Docs/Manager delivery through implementation, required qualification, canonical sync and archival. It is not a planning-only merge. The producer, Store writer and selectors remain unchanged. Inspection supports the exact current format1/2/3 validator; selected export writes format2 and excludes configuration. Existing ordinary export/restore remain separate. Cloud transfer, selected/replacement restore, native pages, provider qualification, mode activation, runtime/service changes and pending generation4 coverage remain required separate work. No source-maintained component version is introduced; Git tags remain version authority.

## Impact
Only central specifications and Manager consumer code/fixtures/manuals change. Reuse the existing protected input, wired identity, fixed stdin helper and maintenance-owner boundaries. Source and evidence pins are in source-proof.json; proposed closed interfaces are in contract.md. No tablet, provider or native operation is required for development fixtures.
