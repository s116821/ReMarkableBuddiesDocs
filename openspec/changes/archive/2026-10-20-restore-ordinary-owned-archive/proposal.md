# Restore an ordinary owned archive deliberately

## Why and bounded scope
The management roadmap requires previewed, recoverable owned-data restore. Archive inspection and selected-history export are already delivered; neither grants activation authority. Existing Store::restore supplies an additive ordinary-format writer but no conditional host prepare/apply/status protocol. Expose only that missing bounded producer capability for an existing ordinary store in unconfigured/local-only mode.

Reuse the same validation, generation staging/rebuild and atomic CURRENT writer. Preserve existing actor, source archive, old generation, existing target history, active configuration, credentials and unrelated/native files. Add original target generation/history and source identity conditions, a fixed prepared target generation, exact readback and honest unknown/status semantics. No selected-format source/target, shared/isolated mode, clean-device initialization, provider download, group join, configuration/credential activation, service control or native-page readiness is included. Those broader restore requirements remain unfinished in document-scoped sync and management.
