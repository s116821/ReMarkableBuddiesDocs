# Design

## Extend the existing writer
Factor the current Store::restore into one internal restore core receiving the already parsed backup, held Inner guard and chosen target generation. Existing public callers retain their current validation/order, fresh UUID and errors. The new conditional sibling uses ordinary open_existing, original mode token and stricter bounded archive admission; compares original conditions under the same Inner mutex; then invokes that SAME staging/copy/rebuild/CURRENT core. Do not call public restore while holding its mutex, create a second activation writer or weaken selected-format refusal.

Prepare reads one bounded raw backup.json, hashes those exact bytes and validates the parsed document using the existing full archive inspection/collision/lineage checks. Require object-shaped backup/schema records on this new path; retain legitimate lists and leave old inspect/export/load behavior alone. Apply reloads once, compares the raw metadata hash, validates that same parsed object and passes it into the core. Content-addressed source/target objects are reverified during actual copying. Do not inspect one archive then independently reload an unpinned version for publication.

## Original state and desired state
An original target generation alone is insufficient: ordinary commits can change history without replacing CURRENT. Bind the complete bounded committed manifest inventory/content identity, original actor/mode token, selected config path/exact bytes and source path/raw archive hash. Recover and verify all referenced objects; reject unavailable/ambiguous/colliding/oversized closures. Prepare the additive union, retaining exact manifest semantics and every existing target record. Refuse a union that fails lineage/revision/operation checks. No destructive replace policy or record rebasing is introduced.

Mint the intended non-nil target generation during prepare, distinct from the base and any existing generation. The original intent carries that identity and exact desired history/staged-configuration digests before apply dispatch. Refuse any already-existing target directory instead of resuming, overwriting or cleaning it. Reserve the new generation root with exclusive directory creation; an absence check followed by the existing permissive create_generation helper is insufficient. Old callers retain their existing helper behavior. A deliberate restore creates that new additive generation even if all incoming records already exist; preview accurately shows zero additional manifests in that case. It is not an implicit retry or no-op promise.

All original target comparisons, staging, rebuild, atomic CURRENT publication and exact target readback share the same Store mutex. Keep Store/process and ordinary-mode custody through the consuming report. Revalidate actual CURRENT against the in-memory original generation before mutation and read back CURRENT/complete desired closure after publication. No process lease alone is claimed to serialize same-process Store writes.

## Reconciliation and uncertainty
Known admission/precondition refusal before entering the restore writer is not-dispatched. Track the actual CURRENT publication attempt separately from staging: set an internal flag immediately before the existing atomic CURRENT call. Failure before that point reports not-activated, explicitly allowing retained partial staging; it must not imply that no files were written. Failure once CURRENT publication was attempted stays unknown, even if old CURRENT bytes remain. Retain stage/old generation/source; do not infer rollback, delete partial staging, retry apply or emit a replacement report after a prefix. There is no persistent operation receipt or publisher-history proof. A complete original not-activated report describes that invocation only; later status/refusal cannot settle a previously lost report.

Status is an explicit read-only existing-store observation under consistent ordinary Store/mode custody. Check the original config/path/actor/mode binding, then CURRENT plus the full intended generation closure and optional staged-config bytes. If all desired identities match, report desired-generation-observed; otherwise unresolved. A later admission refusal, missing archive or changed config cannot settle the earlier unknown attempt. Status needs the original source path spelling only for its hash; it does not read/revalidate the archive or require it to remain present after successful restore. It never restores or initializes anything.

## Identity, configuration and media
Keep the target actor and device/mode files. An optional legacy archive configuration remains only inactive restored-config.json in the new generation, exactly as in the existing writer; never apply it or resolve its credential references. Do not copy credentials, caches, native documents or unreferenced runtime files into active history. The old generation retains its original files/diagnostics. Completeness derives from the verified union's original media coverage, distinguishing intentionally omitted media from missing promised bytes. Do not silently download media or claim current native-page bindings.

## Future consumer
The producer's intent/path/hash/actor/generation fields are host-private conditional evidence, not renderer capability or tablet-identity proof. Future browser/Electron precode must bind an identity-verified wired connection, show the actual target and additive impact, retain the original packet before one explicit apply, and preserve unknown references/cancellation/navigation guards without automatic retries or technical packet displays. No host API, editor or restore UI is implemented by this producer change.
