## Entry, limits and admission
Fixed selectors are --restore-operation prepare|apply|status with exact --restore-input - and EOF-delimited UTF8 JSON. Every operation consumes its own bounded stdin; no input files, aliases or runtime/other-maintenance combinations. Select an explicit absolute configuration through REMARKABLE_BUDDIES_CONFIG; no --config/default fallback. Enter before dotenv/runtime/provider/logging/worker startup.

Input and complete single-LF output each cap16384 bytes. Config caps1048576 bytes; raw archive metadata and unique record metadata/desired union each cap8388608 bytes. Archive/current/union manifests and unique referenced objects each cap4096; each object uses existing256MiB maximum and each record existing1MiB maximum. Preserve existing host deadline hierarchy; do not increase it for large archives. Counts and sums must be safe integers; overflow/refused bounds never truncate. Each explicit path has at most4096 UTF8 bytes and must be absolute/nonempty/non-root, safe under existing no-symlink/reparse policy. Source must be outside and not an ancestor of any target owned root. Config/roots retain existing safe-path checks. No recursive scan/delete of arbitrary locations.

All protocol structs are JSON objects with exact keys, recursive unknown/duplicate refusal, supported versions, non-nil UUIDs and lowercase64hex digests. Reject positional struct arrays; legitimate collection arrays stay allowed. Reuse the strict maintenance decoder narrowly without changing old command wires. Archive format1 only, no selected_history field (even null), no selected source/target. Require a valid existing ordinary Store and only absent/local-only current mode, legacy sync disabled. Busy/shared/isolated/unavailable/corrupt/future state refuses without initialize/repair/service stop or fallback.

## Exact private requests and intent
Prepare is exactly `{restore_version:1,operation:UUID,source:ABSOLUTE_ARCHIVE_PATH}`. It performs no filesystem mutation and returns the current impact plus a new private intent. Operation is caller-chosen; target_generation is producer-minted during this prepare. The caller retains the returned original unchanged before possible apply dispatch.

Apply and status are exactly `{source:ABSOLUTE_ARCHIVE_PATH,intent:INTENT}`. INTENT has exactly these ordered fields:

`{restore_version:1,operation:UUID,config_path_sha256:HASH,config_sha256:HASH,source_path_sha256:HASH,archive_sha256:HASH,actor:UUID,mode_sha256:HASH,base_generation:UUID,base_history_sha256:HASH,target_generation:UUID,target_history_sha256:HASH,staged_configuration_sha256:HASH_OR_NULL,complete_media:BOOLEAN}`.

All UUIDs are non-nil; target and base generation differ. mode_sha256 is the existing original SyncModeToken sha256 paired with actor, decoded only as an original precondition and revalidated to acquire ordinary custody. It is not a live lease. Configuration bytes/paths must match their original digests on every operation; status never follows changed roots. Source/config hashes and UUIDs never prove physical tablet identity.

Config/source path hashes are SHA256 of UTF8 `urn:remarkable-buddies:ordinary-restore-config-path:v1:` or `urn:remarkable-buddies:ordinary-restore-source-path:v1:` respectively, followed by the exact explicit path spelling. config_sha256 and archive_sha256 hash the original raw file bytes, not reserialized JSON. Archive apply loads/hashes/validates the same document once; source objects remain hash/size-verified during copying.

For a valid ordinary history, sort the unique manifest inventory by canonical lowercase hyphenated transaction UUID. A manifest hash is SHA256 of its existing serde_json::to_vec(Manifest) bytes (declared struct order, BTreeMap namespace order, original vector orders), identical to the existing atomic_json writer recipe. History digest is SHA256 of UTF8 `urn:remarkable-buddies:ordinary-history:v1:\n` followed for each sorted entry by `UUID`, one ASCII space, its lowercase manifest hash and LF. Validate all referenced record/media bytes and lineage as well as that identity. Pin an independently calculated golden vector in implementation evidence. target_history_sha256 is the exact validated additive union, with equal duplicate transactions deduplicated and unequal collisions refused.

staged_configuration_sha256 is null iff the source archive has no config snapshot; otherwise SHA256 of the exact existing serde_json::to_vec(Config) bytes to be written to restored-config.json. It is never the active config revision or permission to apply settings. complete_media is the desired union's validated media completeness, not merely the source flag. Recompute every derived target condition on apply; forged or stale conditions refuse before the writer. Bounds apply to the full union, not independently to each half alone.

## Publication and exact observation
Acquire original current-mode/Store custody and the actual Store mutex. Compare current actor/mode, exact config/path/source identity, disk CURRENT, in-memory generation and verified base history before staging; retain that same mutex through the existing additive writer and desired readback. Source metadata mismatch, intervening same-generation commit, generation replacement, target directory already present, path/binding/union mismatch or target hash disagreement refuses without invoking the writer. No conditions are refreshed. Reserve the prepared generation root with exclusive directory creation, not a check followed by the old permissive helper; even a raced existing directory must not be reused or overwritten. New stage and old generation/source remain after any writer failure; never call automatic rollback/cleanup. Track an internal publication-attempt flag immediately before atomic CURRENT: pre-attempt failure can prove not-activated while leaving staged bytes; post-attempt failure is unknown.

After atomic CURRENT publication, verify exact CURRENT target UUID, ordinary format marker, complete target manifest/object/lineage closure/history digest, complete_media and optional restored-config bytes/presence while custody is still held. Report success only after all match. There is no runtime/service restart/readiness claim. Status performs the same complete desired-state observation under consistent existing-store custody, but does not mutate, read source archive bytes or acknowledge historical apply identity. Current target UUID alone is insufficient. A changed/nonmatching valid target gives unresolved; admission/I/O refusal remains a separate refused invocation.

## One report and phases
Report has exactly `{report_version:1,operation:OP,status:STATUS,outcome:OUTCOME,disk_readback_verified:BOOLEAN,runtime_activation:"unverified",data:DATA_OR_NULL}`. STATUS is ok,invalid-input,unavailable,unsupported,busy,conflict,failed. No raw errors, paths/config/record contents, credential references, native IDs or free text appear; only intent hashes/UUIDs are private data. Encode fully/bound before one consuming write. Store/current-mode custody survives complete output or prefix failure; never emit a second report.

SUMMARY is exactly `{manifests:COUNT,objects:COUNT,complete_media:BOOLEAN,configuration_included:BOOLEAN}`. PREVIEW is exactly `{source:SUMMARY,target:SUMMARY,additional_manifests:COUNT,additive:true,configuration_applied:false}`. Target configuration_included means inactive staged configuration, never effective settings.

| Operation/result | status / outcome | disk_readback_verified | Exact data |
| -- | -- | -- | -- |
| prepare | ok / prepared | false | {preview:PREVIEW,intent:INTENT} |
| apply, exact readback | ok / restored | true | {inspection:SUMMARY,configuration_applied:false} |
| status, exact intended active closure | ok / desired-generation-observed | false | {inspection:SUMMARY,configuration_applied:false} |
| status, valid nonmatching active state | ok / unresolved | false | null |
| refusal before entering writer | corresponding refusal / not-dispatched | false | null |
| writer error before CURRENT publication attempt | failed / not-activated | false | null |
| any error after CURRENT publication attempt | failed / unknown | false | null |

not-dispatched asserts only that this invocation did not enter the restore writer. not-activated proves that this original invocation did not attempt CURRENT publication; partial staged files may still remain, so it never means nothing happened. Unknown begins only when CURRENT publication was attempted and can retain old CURRENT bytes or complete new data. Missing/truncated output is not rollback, regardless of a possible internal pre-activation phase. A later status refusal/unresolved does not settle the original unknown attempt. Do not reapply after desired-generation observation or automatically retry a retained stage; repeating the original apply fails its original generation or already-existing target condition. A new explicit restore gets fresh conditions/target generation and preserves earlier diagnostic evidence.
