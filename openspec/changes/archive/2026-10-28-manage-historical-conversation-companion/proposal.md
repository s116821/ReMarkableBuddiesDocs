## Why
Manager can discover ordinary historical conversation root IDs but cannot guide a user through the shipped original-bound logical-removal operation. A separately admitted preview and confirmation flow closes that consumer gap while preserving uncertain operations for explicit read-only reconciliation.

## What Changes
- Add explicit selection from the delivered conversation inventory, fresh selected-target Inspect, fresh Prepare, deliberate confirmation, one Apply and original-intent Status.
- Keep producer intents, Config/store identities, receipts and raw bytes host-private. Publish only target UUID, bounded counts and separately labeled historical acknowledgment/current state.
- Add a twelfth maintenance owner to both actual host factories, preserving the previous eleven owners, all uncertain originals, expiry and observation quiescence.

## Capabilities
### New Capabilities
- `conversation-management-companion`: bounded ordinary historical-conversation logical removal and original-only reconciliation in browser and Electron.
### Modified Capabilities
None. Discovery remains a read-only candidate snapshot with no row action or write authority. The selection control belongs to this separate capability. Producer, aggregate report1/report2, generation support and existing operation wires remain unchanged.

## Impact
Central Docs and Manager only. Reuse existing wired trust/identity callbacks, bounded helpers, strict JSON, maintenance ownership and original-operation patterns. No dependency, version source, backend service API, native lookup or producer change. One paired lifecycle through implementation, independent review, verification, canonical sync and archival. This is a proposed consumer; it is not implemented or device-qualified.
