## Decisions
1. Separate management from read-only discovery. The new section explicitly selects an ID from the current completed inventory; no automatic first row, text matching, paste shortcut or discovery-row action. Capture the selected UUID and matching connection/boot before management admission invalidates discovery. A selected candidate proves neither eligibility nor current native identity. A fresh target Inspect followed by a fresh Prepare is mandatory; prepare counts replace inspect counts. The host enforces the inspect-to-prepare progression using a short-lived opaque reference, not an inventory-derived permission.
2. One host-private coordinator retains original report bytes and exact `{intent:...}` bytes. The public caller never supplies a producer operation UUID/intent/path/selector. Inspect creates a reference but no operation; Prepare mints the operation once. Confirm crosses the possible-dispatch boundary once, retaining that original before child launch. Never expose another Apply using that reference, even after unchanged/unresolved or a lost reply. Explicit Status uses the retained exact bytes and cannot renew expiry or mint another operation.
3. An acknowledgment settles the original historical operation but does not imply desired current heads. Show acknowledged/current-state-changed together when reported. A matching tombstone without an exact receipt remains unresolved. Unchanged is a bounded observation of the original state, never proof of no historical deletion or permission to retry. Refusal/transport failure cannot synthesize empty counts or absence.
4. Reuse the cleanup host's original-only pattern, with a new strict parser for this producer's different framing, hash, receipt and field limits. In particular apply/status input has no request_version; the report cap is32768 bytes, not the cache cleanup16384 cap. There is no safe generic substitution of cleanup statuses or hashes.
5. One real shared MaintenanceIO owner in both factories, captured raw observer, reciprocal invalidation and exact per-invocation cancellation. Cover all132 directed pairs and preserve all110 predecessor cases. Busy must precede hooks, grant changes and child work. Observation quiescence remains local and includes queued-before-dispatch reads; do not use global cancel to obtain it.
6. Avoid a new persistence or recovery file. Retained references and intents live only in the current host process, bounded by capacity/time. Restart or expiry means original Status is unavailable; it never authorizes a fresh operation as a replacement. Explain this limitation in both manuals.
