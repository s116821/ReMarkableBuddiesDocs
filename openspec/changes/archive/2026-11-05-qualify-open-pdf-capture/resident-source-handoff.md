# Installed resident source handoff: proposed precode

Status: proposed source increment, pending independent contract review. No Buddy
or SDK implementation, approved installation, tablet action or native capability
qualification follows from this document. Preserve the frozen Buddy87b63ad
artifact/candidate lineage; subsequent source evidence must use its own exact SHA.
The full REM-25 objective remains automatic creation/reuse in installed Reader,
Writer and blank-start flows, with qualified binding/rendering and recovery.

## Inspected source boundary

Current main constructs RealDevice/Workflow and attaches ServiceHealth; no product
caller owns Session. RealDevice selects LegacyUnqualified capture. Session already
owns installed activation, actual RequestInput, health/integrity admission and the
Observe/CaptureSource dispatcher. Its private Installation loader validates the
fixed recovery profile, firmware/kernel and exact app/unit/native payload hashes.
Config has no resident acquisition selector. NOTIFY_SOCKET/ServiceHealth prove
liveness ownership only, not permission or qualification for native activation.

Reader rendering still inspects the successor first. sdk_buddy_decision and
sdk_acquisition remain Synthetic-only; saved binding matches are Historical or
Unresolved. No stored or captured historical result can mint PageObservation,
NativeCommitted, selection/adoption, BindingCommitted or a render/Writer lease.

Extend the owned installed profile with a separately versioned version3 selection

The version3 selection retains the explicit supported companion contract and all
current strict policy/artifact checks. Do not add a generic qualified boolean,

or change Config/storage configuration ownership for this selection.

A read-only startup selection loader returns a privately constructed
InstalledReaderSelection with pinned profile bytes/digest and explicit mode.
Missing profile or valid old profile means unselected legacy. An explicit invalid,
unknown, changed or unsupported selection refuses; it never becomes legacy.
Selected mode requires the actual supervised ServiceHealth owner. main passes

The version3 startup selection performs no activation, stop, native connection,
input or navigation.
No approved version3 profile/package is produced by this source increment; external

### Explicit startup activation experiment

On RM2 the first lazy activation replaces the stock Reader and returns to
Library, losing the open source of the initiating gesture. A later gesture
works on the retained process. Qualify one activation during a deliberate
installation start, before any conversation trigger, using the same pinned
profile, service owner, exact activation and independent recovery.

An explicit development plan may select startup activation. The installed
plan and rollback must be pinned before activation. Require quiet live
input at the start and through handoff. This guard can cancel activation
and cannot supply a Reader release, capture, placement or render authority.
Retire the initial connection after successful activation, keep the
resident process, and admit the first genuine released gesture through the
ordinary fresh connection. Any failure after potential takeover stays with
the existing recovery owner. Reopening documents is left to the stock UI.
The omitted setting preserves existing startup behavior.

On hardware, show that the first real gesture after startup obtains the
open fixture page and that a second request retains the same process.
Production installation activation remains a separate packaging decision.

### Installed Reader output candidate

An explicitly installed version 5 profile selects output and the startup
handoff through the normal service command. It pins the same RM2 firmware,
kernel, native profile, adapter, executable and recovery policy. No fixture
plan or document identity is supplied. Each genuine released gesture uses
the current native source and order, the ordinary page recognizers, and
the existing insertion journal and Ledger. Installed bindings carry
separate provenance. Unsupported or ambiguous pages refuse.

The installed blank-start selector uses a stationary three-contact hold.
It is enabled only by installed native output. It must overlap the released
input observers and carry its meaning through the same resident request owner.
The Ledger selects an existing binding or a fresh conversation. A positively
recognized current Blank-template notebook page can start without an ink file
when its content region is clear and the file is stably absent. An unbound
blank successor does not acquire authority from this recognition.
The local `--writer-note` command can arm an installed refinement for one
explicit document/page, draft, and operation. A single request slot in the
private activation directory has a two-minute boot-clock deadline. A fresh
Reader-corner release and the exact resident capture consume the matching
request before model work. The native owner checks that the request names the
current generated draft and holds its observed root through execution.
Unmatched releases keep their ordinary meaning and a
new activation cannot consume the previous activation's request. This is the
local Writer command entry point. Typed on-page submission is owned separately.
The candidate remains gated
to the qualified build and device contract until SDK packaging, automatic
recovery, and other normal request paths are qualified.

The installed recovery owner retires the active activation file only after
verifying stock Reader and its companion, and rechecking the recovering
unit, original Buddy group, and pinned activation. It moves the exact lease
to a unique recovered filename in the same private runtime directory.
The recovered file and session evidence remain available. A failed or
uncertain recovery leaves its active latch occupied. A later service start
obtains a fresh activation after independent admission and cannot use the
recovered lease as output authority.

On the RM2, r37/r34 confirmed same-boot start after clean recovery and a
separate recovery after interruption immediately after an observed insertion.
The interrupted notebook retained the original page and one adjacent blank
target. The insertion journal retained the exact historical reply, and the
Ledger required reconciliation with no target binding. The simulator must
represent this split between native persistence and Buddy bookkeeping.

Check historical insertions by document and original or allocated page before
further output, including requests assigned a fresh conversation ID. An
attempt that may have inserted requires a matching stored binding and the
target still adjacent to the source before normal output classification can
continue. A historical reply alone cannot authorize writing or another
insertion.

The RM2 cancellation trace separates a generated answer from output
admission. Canceling during read-only admission preserves the generated
draft with a canceled outcome and makes no native reservation. Only normal
stock open bookkeeping may change. A distinct release starts a fresh
request on the same healthy Reader process. The simulator must model this
case separately from interruption after native insertion, where a blank
target may have persisted and a later request must stop for reconciliation.

Workflow stores one selected resident owner alongside ServiceHealth, in states
AwaitingReleasedGesture, ActiveSession and Fatal. The selected acquisition branch
is invoked by the real idle Reader path and AcquireReaderEvidence call site, not
an unused facade. The default constructor and unselected simulator/legacy branch
retain current behavior. A selected resident failure cannot downgrade to legacy.

## Released gesture: bypass legacy dismissal entirely

The current prepare_reader_trigger calls RealDevice.prepare_reader_trigger and
trigger_dismiss, which can inject an outside-panel tap. It is not the selected
resident handoff. Nor is a generic Interaction::Reader proof of release: although
ContactReducer emits Reader from an empty-contact release frame, NativeHistory
can fall back to Touch.wait_for_trigger_with_progress, which returns after a held
contact reaches two seconds, while DOWN is still active.

Add a selected-only wait/handoff through the existing InputObserver/contact
reducer. It owns the observer before the gesture, services health on every idle
poll, and accepts only a Reader event with quiescent released contacts from that
observer. No Touch/history fallback, synthetic release, screenshot, panel
classification, outside tap, keyboard/pen emission or menu dismissal is allowed.
An invalidated/lost/incomplete/seeded contact cannot supply a release token.

Return a crate-private released-gesture/input handoff, never a public boolean.
Bracket fresh observer construction with old-observer polls and poll the fresh
observer before transferring it into RequestInput; both must remain quiet and
quiescent after the initiating release. Failure is sticky for that request. The
selected path must bypass prepare_reader_trigger and legacy NativeRequest
creation. No existing status/history owner may be silently reused across native
activation; invalidate its cached viewport/undo/owner state first. A selected
immediate-capture/non-gesture entry refuses instead of manufacturing this token.

On the first released gesture only, invoke Session.activate with the same Store,
main-thread health and actual guard. Its existing overlapping post-activation
reacquisition remains mandatory. Retain the Session; never drop it at ordinary
request completion. Later released gestures get fresh request guards and reuse
the same Session/child, without another factory/activation. Keep request-local
cancellation distinct from sticky input integrity/health loss.

Retire the client deliberately at completion of a resident source request using a
narrow Session finish-source-request operation. The next distinct released
request may perform one explicit same-child reconnect before its new Observe;
this is not a retry of a failed request or permission to settle an unresolved
effect. Anchor its reconnect deadline once as min(original_acquisition_deadline,
reconnect_entry+30s), matching the actual Runtime reconnect maximum; never pass
the unbounded90-second remainder or renew/retry reconnect. Failed Observe/Capture never reconnect/retry within that request. No
automatic process restart, replacement source, UI recovery or new target follows.
Dropping/losing Session or activation/integrity failure still poisons the real
health owner and exits for independent recovery. Ordinary cancellation/refusal
retires the socket and ends that request; its guard cannot be renewed/reused.

## One original source-acquisition budget

After the released-gesture handoff, anchor one request deadline before any
selection revalidation, activation, reconnect, Observe, capture, derivation or
persistence work. The total source-acquisition bound is90 seconds, anchored before activation or
any selected setup. Add Session.activate_until(original_deadline): use
min(original_deadline, activation_entry+60s), retaining the existing activate API
as a compatibility wrapper rather than silently resetting its timer. Observe and
Capture each use min(original_deadline, phase_entry+10s); derivation/persistence
and final handoff must fit the same original90 seconds. This is a maximum, not a
promise that60+10+10 plus overhead fits. No retry, readiness sleep or fresh budget
is granted when reserves are exhausted. Continue real health progress (existing
120-second health window and30-second cadence) through activation, input wait and
requests, and retain the separately installed independent recovery policy.
Health/input/service/runtime checks run before/during/after every native request,
and after synchronous derivation/persistence return before provider delivery.
Recheck the original Instant after each such cost and final retention; these calls
are not claimed forcibly preemptible. Failed/late retention cannot permit
provider/output dispatch. Independent installed recovery bounds remain.

Accept only Reply::Observed(facts), then issue exactly one CaptureSource(facts)
with a distinct operation. The existing SDK operation budget remains10000ms; the10-second Observe/Capture
subcaps match that request bound rather than creating larger transport authority.
ReaderFacts supplies historical document UUID, current
page UUID and exact page order. It supplies no revision, visit, input epoch,
persistence, viewport authority or native ownership. SDK correlation checks both
capture source samples against the expected facts. Accept only Reply::Captured;
reject source/order change, malformed image, unknown reply, cancellation, deadline
or integrity loss without fallback. Reconcile remains read-only and cannot clear
earlier unresolved effects.

The current native backend joins an actual Reader and its order; Library/no-Reader
state refuses rather than returning an empty ReaderFacts. An existing blank Reader
page is different from starting without a document. No blank-start or direct
open/create contract is introduced here. The stock overlay may remain open after
a released corner gesture; refusal is preserved, not repaired by a hidden tap.
Qualifying a usable post-activation Reader without legacy dismissal remains a
native acceptance requirement, not an assumed source property.

## Minimal typed historical provider/domain bridge

The existing pure Screenshot.reader_images_from_owned_png recipe already accepts

pixel strips. Reuse it once. No SDK change is required to derive these historical
provider images or feed observed ReaderFacts into CaptureSource. Do not construct
CapturedBatch, ReadOnlyDevelopmentCapture or a v11 completion for this purpose.

Add a private-construction ResidentSourceCapture at the Session/coordinator
boundary. It contains the owned SDK HistoricalCapture plus actual runtime identity,
Observe/Capture operations and expected facts taken from this same successful
request route. Deserialization, bare PNG/facts tuples and caller qualification
flags cannot construct a live/coordinator result. Do not invent raw canonical wire
frames, connection/server nonce or native dispatch receipts that the current API
does not expose. Runtime/operation correspondence is explicitly historical.

Propose ResidentCaptureHistory in the existing REM-37 Ledger, new
Record::ResidentCapture under Source envelope domain_schema_version2 with its own
strict payload schema1/kind. Source envelope version2 is already supported by
Store; no new namespace, Store generation/version, registry, database, transaction
engine or external side record is needed. Require Source namespace, envelope schema2 and resident payloadschema1 as one
exact pairing. Decode its branch before the existing catch-all INTENT_SCHEMA
branch; preserve Source1, NormalizedText and all intent/export/binding schema
rules unchanged. Old readers fail closed on unknown record kinds. This is a proposed extension of
the existing domain owner, not permission to fork its APIs or edit unrelated WIP.

- origin ResidentHistoricalUnqualified and explicit absence of native/output

Expose prepare_resident_historical/stored_resident_images on Ledger, following the

Add AcquiredEvidence::ResidentHistorical and a typed Attempt evidence-kind branch

## Required source/model controls

Exercise the actual main/Workflow selection and released-gesture branch with a
private injected factory and owned protocol child; do not test only a pure helper.
- Absent/old selection never calls factory; malformed/unsupported selection
  refuses before legacy/provider/native effects; startup never activates.
- Held contact and the legacy Touch fallback cannot call factory. Actual full
  release plus quiet overlapping observers can; no dismissal tap is recorded.
  Cover seeded contact, SYN_DROPPED, old/new observer failure and post-release input.
- First request activates once; next released request reuses the same child and
  explicitly reconnects once. Cancellation never retries or revives its guard;
  fatal loss exits and cannot leave ordinary runtime alive without Session.
- Observe facts feed exactly one CaptureSource; changed facts/order, Library,
  unknown replies, cancellation, EOF, expiry and malformed images admit no provider,
  legacy capture, target allocation, insertion, adoption, binding or render.
- Whole-route delayed service/request/derivation/persistence costs consume the same
  anchored budget, including final retention and health reserve.
- Exactly four acknowledged stored provider images reach actual provider/independent
  verification; no second device query. Host fake-provider response can reach
  Generated history but never selected/legacy output authority.
- Real Store restart, CAS contention/lost acknowledgment, malformed schema/kind,
  wrong binding, stale IDs, changed/corrupt/missing media and partial restore retain
  originals and refuse substituted evidence. Exercise decoder/schema mismatch,
  selected capture image projection, ordinary/selected snapshot/export, deliberate
  omitted-media restore and exact reopened bytes. Preserve Source schema1 byte
  serialization; no existing Source1 record is upgraded or rewritten. Existing v1/v2 SDK/development/legacy
  evidence and unresolved native-effect journal bytes remain unchanged.
