## ADDED Requirements

### Requirement: Explicit shared saved-only configuration view
Both companions SHALL offer explicit bounded inspection through the exact producer
contract, show safe saved declarations and their origins, and keep runtime/provider/
root/credential validity unverified. Inspection SHALL NOT grant settings mutation,
active mode, reload or service authority; absent schema settings remain explicit gaps.

#### Scenario: Deliberate saved snapshot
- **WHEN** an admitted observed target is explicitly inspected
- **THEN** both hosts show the same validated safe fields/origins and unverified-runtime/path explanation without automatic inspection or raw JSON.

#### Scenario: Unsupported setting or runtime override
- **WHEN** a setting is not represented by the saved schema or runtime/environment may override it
- **THEN** the view shows the explicit schema gap or saved-only value and never invents a false default, effective model or active service/provider state.

### Requirement: Strict private reduction and origin consistency
The host SHALL validate the complete producer report and reduce it to the exact
public shape with no raw file digest or private strings/identities. Both host
bridges and controller SHALL validate all25 literal flat fields, pinned defaults,
null/presence/range and cross-field consistency, refusing the whole malformed view.

#### Scenario: Omitted versus explicit null
- **WHEN** optional values are absent, explicitly null or declared nonnull
- **THEN** the safe value and default/declared-null/declared origin remain exact, even when projected values coincide.

#### Scenario: Inconsistent derived or grouped fields
- **WHEN** path origins differ, text presence/bytes/origins disagree, namespace ordering/uniqueness fails or pure memory/sync constraints disagree
- **THEN** the complete view refuses without coercion, filtering, rounding or partial success.

#### Scenario: Private or future report
- **WHEN** a raw digest/report, unknown fields or unsupported protocol/schema enters a public bridge or response
- **THEN** private content never reaches renderer state/logs and a fixed refusal or explicit unsupported capability replaces the entire view.

### Requirement: Host invalidation before settings I/O
The new maintenance entrypoint SHALL invalidate prepared-forget host authority
before inspection I/O and preserve possible-dispatch uncertainty under the existing
original-intent contract. Host observer generations and exact target/boot checks
SHALL reject stale configuration completions before public output.

#### Scenario: Configuration read after ready preparation
- **WHEN** a ready forget reference exists and another client starts configuration inspection
- **THEN** the shared host invalidates that reference before dispatch and later confirmation cannot send the old conditional operation.

#### Scenario: Configuration read during uncertain mutation
- **WHEN** an original confirmation may have dispatched
- **THEN** the settings action cannot replace/rearm/settle it, and original private bytes remain available only under the existing receipt-only rules.

### Requirement: Bounded protected transport and cancellable lifetime
Both paths SHALL use the fixed no-stdin remote selector, strict identity-only
requests, existing wired before/after checks and the contract's byte/time limits.
Read-only cancellation, navigation, same-ID refresh/disconnect and new operations
SHALL suppress old host/controller results without retry or default fallback.

#### Scenario: Malformed or unsupported transport
- **WHEN** old binary support, UTF8/duplicate/framing/cap/exit/deadline or authorization checks fail
- **THEN** no partial/default snapshot, automatic repeat, arbitrary-file/staging or running-service fallback occurs.

#### Scenario: Same-ID refresh or navigation
- **WHEN** an explicit refresh/document navigation or disconnect occurs while a read is pending, even with unchanged IDs
- **THEN** host and controller generations prevent that read from restoring the cleared view and preserve any mutation uncertainty.

#### Scenario: Cancellation versus subsequent read
- **WHEN** cancellation is followed by another inspection or tablet read
- **THEN** the shared cancellation queue completes earlier cancels first, so a late cancel cannot kill a newer read or restore old fields.

### Requirement: Attributed paired verification and own lifecycle
Consumer acceptance SHALL verify original actual producer specimens separately from
synthetic transport/UI faults, retain real public guards and both ordinary OS
retained-package paths, preserve unrelated source/canonical ownership and complete
its own specification lifecycle in the linked delivery.

#### Scenario: Producer and consumer compatibility
- **WHEN** actual producer specimens become available
- **THEN** their original hashes/status/field/origin semantics verify the strict consumer while synthetic races/caps remain separately attributed and neither proves native/device/runtime qualification.

#### Scenario: Final coordinated delivery
- **WHEN** this capability is proposed for normal merge
- **THEN** required reviews/current checks pass, own canonical requirements and archive match the implementation, actual producer composition is preserved, and later actual-main/tag/provenance observations remain distinct from PR evidence.
