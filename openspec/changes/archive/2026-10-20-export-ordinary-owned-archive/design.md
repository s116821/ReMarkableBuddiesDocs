# Design

## Reuse the source writer under one ordering
Factor only a narrow private guarded core from Store::export; old public caller ordering/admission/format/bytes stay unchanged. The new producer validates the current ordinary format1 root and full committed history/content/lineage under the existing Store mutex, including same-generation commits and absence of selected feature metadata. Reuse the delivered ordinary-history fingerprint recipe/bounds through narrow private helpers, not a second generic history authority. Validate source objects and optional stored config.snapshot.json before destination reservation. Prepare is read-only.

Apply rechecks every ORIGINAL binding under the same mutex before export. Keep existing ordinary-mode and OS Store custody through the consuming report; no source-lock release/reopen between checking and copying. Preserve source CURRENT/history/actor/config/snapshot/mode/objects and unrelated credentials/caches/native documents. Export contains only the existing format1 Backup manifest/object inventory and optional portable config snapshot. No selected metadata, credential files/cache/binaries/native documents, runtime or provider results are added.

## Fresh destination and same publication
The explicit destination parent must already be a regular safe directory; destination itself must be absent. Validate lexical and canonical parent/component ancestry against all three owned roots with Windows ordinal case handling and safe-path/reparse/symlink refusal. No old helper is silently widened. Recheck inside actual writer ordering and exclusively reserve exactly the new destination with create_dir; never reuse a partial/occupied directory or remove a competitor's files. The legacy export core remains the ONLY object-copy/backup.json publication writer. A post-check occupied path must fail without overwriting it.

Partial copy/stage failure before attempting backup.json publication is not-published, not a claim that nothing was created. At/after the atomic marker attempt, errors/readback mismatch remain unknown; no deletion/retry/rollback. Exact verified archive readback includes marker bytes, schema/manifest/object/lineage and honest promised versus omitted media. Source mutation is never a recovery action. A consuming output failure gets no second report and cannot be relabelled as transport success.

## Private original context and pure later observation
Intent carries only version/UUIDs/hashes/boolean and never the destination or raw config/snapshot text. Caller privately retains the exact original destination separately. Status needs only that destination and original intent, not config/Store/source roots/mode/provider. It verifies exact marker hash plus complete format1 closure, and can observe desired archive now; it cannot establish historical publisher identity, original apply completion or runtime/native authority. A later refusal cannot settle an earlier missing report. Future host private-reference/buffer lifetime and deliberate reconciliation require separate concrete precode.

## Evidence
Pin original history and exact Backup-byte/digest references independently. Test same-generation writes, config/snapshot/mode/actor/path/target changes, real Busy and mutex competitor, selected/shared/isolated refusal, ordinary/local success, no initialization and zero source byte change. Exercise all owned-root aliases/case/reparse/symlink/parent/occupied and actual post-check directory race, partial copy versus actual marker/readback/prefix faults, intact competitor files, strict shape/cap/EOF/mixed flags and no output value echo. Retain exact native host CLI bytes/executable start/end hashes and original failures. Round-trip a newly exported format1 fixture through already-delivered ordinary restore only as a new changed-path integration test; do not replay old completed observations or claim native/provider qualification.

## Portable configuration privacy
The optional stored Config snapshot retains existing decoded declarations verbatim, including opaque endpoint/model text and credential-reference metadata. Credential-like text can therefore already exist inside that portable configuration; archive contents remain private, not a sanitized UI report. No credential files or resolved secrets are read/copied, and no archive/config content is echoed in reports. Do not silently redact or normalize the legacy Backup snapshot.
