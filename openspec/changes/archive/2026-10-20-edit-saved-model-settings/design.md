# Design

## Reuse the existing maintenance engine
Expose only narrow crate-private reuse of the existing ordered declaration serialization, pure strict document validation and config-maintenance custody; do not duplicate an atomic writer or generalize the public three-field basic protocol. Basic reports/intents, hash recipe, shapes and field allowlist remain byte-compatible. Existing general saved inspection remains presence-only and grants no editing context. The new explicit editor inspect observes its own original file/path identity.

Each dirty field is set to its exact provided string or cleared by removing its key. An absent patch key stays unchanged; set-null is invalid. Validate the entire resulting Config with existing rules. Preserve unrelated decoded values, missing/null origins and exact decoded multiline text. A real edit may normalize JSON order/escaping/whitespace through the existing independently ordered recipe; a logical no-op preserves original bytes and performs no Store write.

## No value echo, including through private intent
Opaque model/endpoint strings may accidentally or deliberately contain secrets. Even a private producer stdout packet can be logged, so do not echo old OR new strings in inspect/preview/apply/status/error output. Return only fixed per-field origins/presence and private hashes/UUID. Unlike the basic enum/bool intent, this intent carries only a canonical patch digest, not changes. The host retains the original raw patch privately before prepare; apply supplies it separately and the producer verifies patch and desired-file hashes against the original intent. Status needs no raw patch. Future host design must preserve/wipe bounded private buffers and unknown history deliberately, not forward hashes or raw values through renderer reference APIs.

No new URL parser, scheme/userinfo/query/fragment policy, control filter or whitespace trimming is introduced. Current opaque nonblank/byte-cap rules apply to newly set values exactly. A valid existing credential-like or unusual string can remain untouched or be cleared without disclosure; unrelated edits preserve it exactly. Blank/oversized/malformed/unsupported documents already invalid under full validation refuse; this is not a selected-field repair mechanism. An HTTP-looking value is not verified connectivity or provider eligibility.

## Same conditional writer and honest results
Apply recomputes the exact modified document from the ORIGINAL file revision and original patch; no silent fresh inspection or patch rebasing. Use current validated existing Store and ordinary-or-selected supported-mode custody, unchanged declared roots and the SAME replace_config_document writer/mutex/CAS/readback. Keep old caller/basic behavior intact and hold Store/mode through the consuming report. Busy remains Busy; never initialize/repair, retarget roots, switch mode, resolve credentials, contact provider or restart service.

Known pre-writer refusals are not-dispatched; possible atomic publication/readback/output failure remains unknown, with no rollback/retry/second report. A complete verified disk save is restart-required; nothing verifies active runtime or environment. Status reads only the original selected config and compares exact original desired bytes; it writes nothing, requires no Store/declared-root probe and proves no historical publisher identity. A later refusal/unresolved observation cannot settle a missing original apply. A fresh explicit edit has a distinct original context and preserves prior uncertainty.

## Evidence and compatibility
Meaningful controls must establish zero old/new string echo (including URL userinfo/query/fragment and CRLF/trailing text), exact preservation/no-op/set/clear/missing/null behavior, canonical patch binding/cross-kind refusal, original CAS, ordinary/selected four-mode custody, real publication/readback/prefix faults, strict shapes/caps/EOF and unchanged general/basic reports. Retain original failures and exact actual CLI reports/executable provenance. Compatibility receipt and future host implementation remain distinct from producer tests, effective provider readiness and physical qualification.
