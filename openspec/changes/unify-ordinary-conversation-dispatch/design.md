## Native composer consumer

The development composer consumer uses the existing resident connection and the
Store-owned native-effect journal. It does not create a second conversation
store, authority registry, automatic activation path or production SDK pin.
Provision and conditional clear reserve their exact wire request and digest
durably before sending. The journal records typed completion or refusal, retains
unknown outcomes, and refuses reused operation IDs across reconnect/restart.
Read-only observation and key waits do not reserve a page mutation. A historical
reply never supplies fresh page, visit or edit authority.

The composer journal extension is explicit schema 3. Existing insertion and
selection evidence remains readable, with its original bytes and restrictions.
Only the development build understands composer records; a build without that
capability refuses them instead of deleting, downgrading or reinterpreting them.
Use an explicitly selected development Store until the SDK and consumer have
completed their production integration. Unknown earlier effects still block
later effects for that conversation. Known composer completion permits a fresh
operation but never replays the consumed original.

The copied draft remains raw UTF-16 until strict product conversion. Conditional
clear requires the exact submitted text to be appended as a new durable User
turn by that submission in the same Store and conversation. A historical turn
with identical text cannot authorize a new clear. The existing append commit
result distinguishes this call's fresh write from an idempotent or concurrent
winner's receipt; uncertain acknowledgment grants no clear proof. The existing
page binding and retained submission are rechecked after caller progress at transport boundaries;
native clear still requires the expected live range/revision/text.
Persistence failure, malformed text or changed ownership leaves the draft alone.
Pre-key observation is not a post-key clear lease: the selected Submit handler
must separately observe and compare the state after stock key handling and
advance its own source revision only from the genuine clear result. Submit
grammar, caret placement, presentation and model dispatch are still unfinished;
this transport/journal increment must not be presented as completed typing UX.

An idle key wait may be re-armed with a new operation and handshake only through
the existing runtime owner. The same native visit and opaque range must survive;
socket replacement, stored IDs or timeout alone grant no effect authority.
Provider calls and render/export remain downstream of durable input admission.

## Finite tablet mechanics trial

The explicitly compiled observer trial uses the admitted Buddy runtime and its
existing independent bootstrap controller/recovery. It uses a fresh nonce-owned
persistent Store beneath the admitted staging directory, retains exact effect
requests/outcomes before assertions, and never shares the product Store or
replays an effect. Bounded ordinary seed typing is developer setup on the
disposable selected page; fresh observation and unchanged native quiet-undo and
logging checks still decide whether provision is possible. Seed text remains
outside the owned interval and in the exact same-page preservation accounting.

The trial keeps input quiet until a protected native diagnostic matches the
actual SDK-prepared AwaitKey frame/digest. Native diagnostic details are owned by
the SDK's guard-owned-composer-edits change. The consumer pins the log descriptor
and fresh EOF, reads positionally with finite append/line limits, and rejects
partial, stale, foreign, duplicate or replaced-inode evidence. Log opening is
nonblocking until the regular-file check, fresh EOF must be a complete line
boundary, and an unterminated trailing line cannot be hidden behind a good
record in the same sample. The receipt means
armed at its sample with a bounded remaining budget, never still-live authority.
Only then does the observer overlap into its explicit typing phase and publish
the operator-ready instruction. Cue contents are durably staged privately;
original local and native deadlines are checked again after input handoff and
staging, immediately before atomic publication of the complete ready file.
Existing runtime and authenticated-transport checks run before as well as after
the progress callout; the cue cannot bypass an already-required failed check.
Unavoidable later changes still do not turn this sample into a live lease.
Return remains a diagnostic ordinary newline,
not a selected product Submit shortcut.

For this synthetic trial, KeyObserved must contain exactly the instructed text
from the same range. A later same-range observation must contain exactly that
text plus one newline and a genuinely different native revision. Revision+1 is
never assumed. The exact fresh text is durably appended as a User turn before
the once-only conditional clear. Both actor and observer overlap replacement
quiet guards, drain the old typing observer, reject queued gestures/loss and
require released input before dropping it; the observer retains this ownership
through permit teardown. Failure preserves evidence and independent recovery.

These source mechanics are not yet actual-tablet acceptance. Physical folio and
pen OSK behavior, native selected-instance/profile admission, typing/idle/clear,
outside-range preservation and recovery remain to be exercised on the tablet.
Injected input, if selected, cannot qualify physical keyboard reachability.
Model dispatch, rendered replies, product shortcut and practical page scale
remain unfinished v1 integration.
