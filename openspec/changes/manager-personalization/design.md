# Decisions
1. Wait for the exact published CLI request/response envelope, command path, bounds, optional-field/default compatibility, disabled/cleared text semantics and readback receipt. Map it strictly rather than inventing a parallel command/schema. No implementation or saved-looking stub precedes this seam.
2. Both distributions use one shared editor/controller and existing authenticated helper/main-frame host boundaries. Inputs carry only the fixed action, permitted text/enabled setting and expected digest; no arbitrary path, shell command, endpoint or service administration. Prompt/config data uses bounded stdin, never command arguments or routine logs. Actual transport bounds are derived from the frozen backend JSON envelope, including escaped JSON expansion and UTF-8 bytes.
3. Bind loaded configuration and every mutation to the current verified wired connection/boot identity and whole-config digest. Reconnect, changed boot/profile, stale readback, refusal, lock contention, concurrent config update and cancellation invalidate success/active assumptions. Preserve drafts on conflict when safe, require fresh inspection before resubmitting; no automatic stale-write retry.
4. Preserve exact multiline Unicode text including CRLF/leading/trailing characters, reject malformed UTF-16/UTF-8 or oversized requests according to the real field contract. Disable versus clear follows the actual command's distinct semantics; do not silently erase retained text/history/handwriting records.
5. Display successful verified disk persistence as saved with the backend's activation state. Initial restart-required means running configuration is not verified active. This increment does not restart/quiesce a service or claim the prompt changed an in-flight or next request; Main owns subsequent activation/context receipts.
6. A timeout/cancelled transport after write may have unknown commit outcome. Do not claim no write or automatically repeat; freshly inspect/read back the known configuration to establish custody. Successful command return alone is insufficient if schema/digest/identity/readback contradicts the current snapshot.
