## ADDED Requirements

### Requirement: Closed source-target generations
The Store SHALL admit domain4 target values only in explicitly prepared family6 with its exact contract and immutable ordinary-notebook or compound-selected base kind. Preparation SHALL preserve actor/CURRENT/generation, original receipts/history and one original OS lease through interruption recovery. It SHALL exclude enabled legacy sync from automatic promotion and retain its supported non-target path. Selected receive/restore SHALL enforce the same family gate.

#### Scenario: Interrupted application startup
- **WHEN** startup resumes a partial source-target preparation
- **THEN** only its original pins/operation complete under preparation-aware open, without nested re-lock or capability repair by an older reader.

### Requirement: Ordinary target archives and plan-bound restore

The application SHALL use a closed ordinary target archive format6 with validated
source-target feature/origin metadata and exact actor/generation, record/media,
lineage and target closure. Existing format4 bytes and admission SHALL remain
unchanged. Neighboring owner files or arbitrary fields SHALL NOT supply admission.
New target originals SHALL be generation-local; exact compatibility reading of the
existing global original SHALL neither overwrite it nor accept conflicting originals.

#### Scenario: Additive target restoration retains exact capability and history

- **GIVEN** an ordinary same-actor conditional restore plan binding archive SHA, base generation/history/family/provenance, target generation/history/family and staged configuration
- **WHEN** the existing restore owner combines format4 with family4, target archive with family4, format4 with a target base, or a target archive with a target base
- **THEN** legacy4→4 remains unchanged and each other combination stages a validated target generation with both exact histories, media and its own plan-bound restore original
- **AND** source live owner files are not transferred, configuration stays staged, and selected/group/cross-actor routes remain refused here

#### Scenario: Interrupted restore repairs only its original local operation

- **GIVEN** a typed plan-bound target staging context under existing-only Store custody
- **WHEN** staging, CURRENT or capabilities publication is interrupted and the application reopens
- **THEN** it finishes or reports only that same original operation and unchanged archive/base/target/family/provenance/configuration conditions
- **AND** complete target closure, origin receipt and contract precede CURRENT, with no broadened ordinary maintenance admission, replacement identity, new live policy/model/HTTP permit or reset allowance/deadline
