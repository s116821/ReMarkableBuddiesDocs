# Closed companion handwriting-record management contract v1 (proposed)

## Fixed transport
Add fixed action `handwriting-records` and private raw reply `handwriting_raw`. Remote argv is the existing fixed Buddy executable with `--handwriting` only, with existing fixed private configuration selected by REMARKABLE_BUDDIES_CONFIG; no renderer paths/config/shell/command/provider flags. One strict JSON stdin request followed by EOF. Allow only query, inspect, forget and status; deny confirm/update and arbitrary operation fallback. The logical command is inside stdin, not interpolated shell text. Verify existing wired connection/boot before and after I/O.

Private request object exactly {command,input_base64,budget_ms,connection_id,boot_id}; command is one of four allowed selectors and must equal decoded input.command. connection_id is64 lowercasehex; boot_id is canonical lowercase nonnil UUID. budget_ms integer1..12000 and no greater than remaining monotonic budget. Input <=16384 UTF8 bytes; raw stdout <=262145 bytes (producer256KiB JSON plus one LF); stderr <=8192bytes, never echoed; input envelope <=24576bytes, raw result envelope <=360448bytes. Public request <=16384bytes, public result <=270336bytes. Enforce all ceilings on encoded bytes before unbounded parse/copy; drain/terminate boundedly on overflow, never accept truncated success. Helper8seconds, transport12seconds, host13seconds, UI14seconds absolute monotonic deadlines. Cancellation/EOF/output/error teardown use the existing supervised process boundary. Increasing unrelated timeout/bundle limits is not an implementation shortcut.

Reject malformed UTF8, BOM, duplicate keys at every depth, unknown keys, depth>32, invalid base64, nonfinite/negative/non-safe integer, malformed UUID/hash, extra output, trailing physical data or anything other than one complete JSON report plus one LF. Escaped embedded newline is content, not a second report. Report version1 required; unknown version/selector unsupported. A transport version/identity/error failure supplies no mutation rollback evidence.

## Producer inputs
All fields exact, no extras:
- query: {handwriting_version:1,command:"query",profile,query_text,max_matches:8,max_encoded_bytes:65536}; query_text null or nonblank exact UTF8 <=2048bytes with no NUL/unsupported controls (CR/LF/tab allowed). UI blank maps explicitly to null.
- inspect: {handwriting_version:1,command:"inspect",profile,correction}.
- forget: {handwriting_version:1,command:"forget",profile,correction,operation,expected_heads:[revision]} generated only from current complete single-head prepared inspect. No public raw request entry.
- status: {handwriting_version:1,command:"status",profile,correction,operation} generated only from a retained original forget.
Profile/correction/operation/revision UUIDs are canonical lowercase nonnil. No source sample decoding/upload, credential access or data-root override is permitted.

## Raw report admission and projection
Follow the exact delivered report-schema.md outer keys, Fact/ConfirmedCorrection/Media/Provenance/Diagnostics keys, failure vocabulary and command/outcome matrix with explicit nulls. Reject extra/duplicate keys at every depth. See source-proof.json for the pinned schema. Validate record_id independently using UUIDv5(URL,"urn:rmb:handwriting-correction:v1:"+profile+":"+correction). Validate every typed value identity, strict text limits, provenance source null/exact3UUID, PNG descriptor hash/size1..524288, dimensions1..2048/pixels<=4194304 and kind. Descriptor validation is not local image verification; availability is the producer's captured observation. Parents unique canonical UUIDs; facts<=16; no duplicate record/revision pair. Query has <=8 distinct record keys, requested profile only, supported value, available, head:true/conflicted:false. Inspect/status/forget facts must match the requested derived record; value.profile/correction must match key. Query ordering is canonical record UUID, not asserted time.

Admit only closed producer matrix combinations including status/command/failure/operation/transaction/record/historical and diagnostics.mutation_outcome. Inspect/query use null operation/transaction, historical:false and not-requested. Query complete/complete-empty has zero omitted/conflicted/unsupported/missing_media; complete-empty nofacts, complete nonempty; partial must have a genuine incompleteness reason (including omitted/conflicted/unsupported/missing samples). Inspect absent is complete-empty, nofacts; all heads head:true, conflicted equals captured count>1, including unsupported members. Tombstones value:null/availability:not-applicable; unsupported value:null/availability:not-examined. A single supported value with unavailable/not-examined media is partial and cannot prepare removal. Read refusals do not supply usable values or preparation. Preserve exact validated producer counters; no estimated corpus totals, no inference about omitted sample availability.

A new forget success requires complete/failure:null/operation original/transaction UUID/historical:false/one matching tombstone fact/revision computed from the documented operation fingerprint/head set, parents equal captured expected head/head:true/conflicted:false/mutation_outcome:observed. Accepted identical replay is complete/transaction:null/historical:true with retained head/conflicted:null and exact original tombstone revision/parents. Store actor is not exposed. Status accepted requires complete, historical:true, transaction:null, original operation, matching original tombstone revision/parents, head/conflicted:null and observed. An accepted value or different revision under that operation is not this removal's success. Retained tombstone status is historical, never current-state authority. Status complete-empty has nofacts/historical:false and unknown. Operation collision or incomplete/unsupported history remains unknown. Do not silently replace forget's unknown original outcome with a current inspect/query observation.

Proved forget refusal before commit has not-dispatched only for this submission. commit-unknown is failed with nofacts/nulltransaction/historical:false and unknown. Valid output may prove accepted historical original; invalid/lost/timedout/cancelled output after possible dispatch means unknown. Any contradiction in a purported success yields unknown, never optimistic completion. Preserve sanitized read/refusal diagnostics; do not echo raw stderr, paths or unsupported payload.

Public view is a strict projection, not raw report forwarding. Detail contains validated profile/correction, derived record, captured supported text/provenance/sample descriptor/availability, and per-head revision/state/conflict metadata; unsupported bodies are absent. Status/forget output contains only safe original reference/outcome/check metadata and sanitized diagnostics, never correction content after confirmation. Query/inspect public fields are closed in contract-public.md; no arbitrary maps. Retained rows contain exactly {reference,connection_id,boot_id,original_outcome,expired}. Later check_outcome exists only at the top level and is never stored in a retained row. Private operation/profile/key/heads/request hash do not leave the host after content confirmation clears.

## Public actions and result contexts
Common executing request fields: action,connection_id,boot_id,invocation (fresh canonical UUID). query adds profile,query_text; inspect/prepare-remove adds profile,correction; confirm-remove/check-remove adds reference (opaque64hex). cancel adds reference (nullable only before reference creation) and uses the original captured invocation, never a fresh cancellation ID. retained is exactly {action:"retained"}. No public operation/expected_heads/hash/raw report/sample/command/config input. Query/inspect are reads and do not create removal authority. prepare-remove calls inspect anew; only a valid complete single-value head can create ready authority.

Each response binds contract_version1, verified observation (or null/refusal), original action/invocation/reference, state, content view or null, removal outcome or null, status check or null, diagnostics or null, and bounded retained rows. Exact key sets, state matrix and literal fixture expectations are frozen in contract-public.md and vectors.json as part of this precode. Result must match captured context and original row/outcome at entry, not mutable renderer state read after await. No late reply may regain a prepared capability.

State classes: idle, queried, inspected, partial, prepared; busy, unsupported, unavailable, invalidated, expired, capacity; not-dispatched, unknown, removal-observed, historical-removal-observed, unresolved. Completion is only the precisely validated new/historical tombstone outcomes above. Busy/no-dispatch must not change an earlier unknown operation. Check outcomes are independently historical-removal-observed or unresolved and preserve original submission disposition. No action automatically retries, changes profile/key/head/operation, re-prepares or refreshes. One explicit future independently prepared operation can use newly inspected current heads, but no UI retry control may regenerate one from unknown history.
