# Saved correction management design

## Current source and proposed behavior
The retained Buddy68e42968 source has a standalone early `--handwriting` path. It loads the configured Store, refuses active legacy sync and unsupported runtime modes, admits local-domain ownership and emits the v1 report. Its query returns verified supported single-head values; inspect reports all captured heads; forget publishes a retained tombstone under exact expected heads; status looks up the original operation without committing. These are observed source facts, not evidence of recognition effectiveness. The current REM-26 live-recognition gate is not met and is unrelated to this proposed consumer.

The Manager currently has fourteen maintenance owners and one fixed wired host bridge shared by HTTP/browser and Electron IPC. Extend that architecture with a fifteenth `handwriting-records` owner, never an independent background worker or a dynamic remote command. Reuse strict JSON/framing, protected stdin, observation checks, monotonic deadlines, MaintenanceIO and the existing finite original-operation pattern. Do not copy old memory-forget's producer Prepare contract: handwriting has no Prepare operation. Local preparation consists of a real inspect and host-captured immutable request only.

## User flow
1. Observe the wired target. Open Saved handwriting corrections. Explain that these are explicit confirmed records, not trained-model state. Enter a profile UUID and optionally search text; blank means all in that profile. No profile/account discovery or default personal identity.
2. Search issues one bounded query. Show exact original/corrected text and caller-asserted provenance as escaped text, with availability and partial/count diagnostics. A partial empty result means some records were withheld; it is never a healthy empty corpus. Query has no paging promise; refine search or inspect an explicit correction UUID.
3. Inspect a selected correction (or explicit key). Show captured heads and truthful media state. Only a complete, supported, single value head can offer a separate Prepare removal action. Conflicts, unsupported records, partial/media-unavailable inspections and existing tombstones are inspection-only. This initial consumer deliberately requires a complete inspect before removal; it does not claim the producer lacks other supported CAS cases.
4. Prepare performs a fresh real inspect under ownership. The UI presents exact original/corrected text, asserted provenance, profile/correction identity and revision plus the consequence: remove from active queries, retain historical text/samples and backups, do not erase unrelated data. A separate deliberate Confirm removal uses the host reference only. The user never supplies expected_heads or operation IDs.
5. Before any possible dispatch, reserve an original slot and mark the original unknown/consumed. Submit exactly one captured forget request. Confirm is consumed even if the reply is lost or the caller cancels. An exact acknowledged tombstone is shown as removal observed at that commit, not a permanent claim that the record can never be recreated.
6. Check original operation is a separate status command using original profile/correction/operation on the same connection/boot. Accepted retained tombstone proves that operation was observed historically. It does not prove the tombstone is still current. Absence, collision, unsupported history, disconnect or corrupt output leave the original unknown. Status never grants another forget or replaces a later unrelated result. No automatic follow-up query or mutation.

## Private data and exactness
Text/provenance/IDs are user-requested content intentionally delivered to the current UI; raw reports, hashes, arbitrary payloads and media bytes are never public DTOs. Use exact UTF-8 with no trimming/normalization except a whitespace-only search becomes explicit null before submission. Display multiline text safely with framework text binding, never HTML. The UI must warn that it is showing private record content. Do not persist draft/results/receipt references in localStorage, sessionStorage, URLs, browser history, logs, telemetry, package artifacts or error strings. Routine errors are fixed sanitized codes. Test reports use unmistakably synthetic canaries only.

Clear draft text and IDs from signals and actual DOM on submit, Stop, peer admission, refresh/disconnect/identity change, hide/unmount and host invalidation. Clear old result content before replacement; late replies cannot repopulate it. Confirmation content is shown only during the 120-second prepared lifetime. On confirmation, clear it before dispatch. The host retains minimal private identity/request bytes for original-operation checks, not the original/corrected text after confirmation. Byte buffers are overwritten when released where possible; JS string/GC lifetime is not represented as cryptographic erasure.

Raw u64 fields can exceed JavaScript safe integers. This consumer refuses any report containing non-safe integers rather than rounding, inventing dates or allowing unsafe confirmation. This is a documented consumer limitation, not a producer version change. Unknown versions/fields/states/matrix combinations also refuse. No fallback to a newer schema or arbitrary remote file reads.

## State and custody
Use one editable inspection/preparation slot and at most eight retained original mutation rows. Each prepared packet has a fresh opaque 256-bit reference, captured connection/boot, profile/correction, operation UUID, one expected head, exact compact forget JSON and SHA256, captured validated preview digest and a monotonic deadline. Before confirmation check current observation, active custody, exact packet hash, preview/reference identity, unconsumed state and deadline. Never reconstruct the packet from a renderer response.

Prepared expiry is 120 seconds from completion of fresh inspect and never renews. The packet is admitted only if capacity for eventual retained original exists. At confirmation mark possible dispatch before calling transport, consume ready authority, and fix original expiry at 30 minutes from dispatch admission. Retain at most eight safe metadata rows for the host session, including expired originals; no silent eviction/reset. Each original allows at most32 distinct status invocations; repeated invocation is rejected without I/O. Expiry/capacity fail closed. Restart loses transient authority; no persisted receipt/retry is reconstructed. Private original bytes and IDs expire; safe row reference, outcome and expired marker may remain. Query/inspect observations are not original mutation receipts.

Cancellation names the captured target, reference (nullable only before creation) and invocation. It revokes only that exact active request or fences its delayed arrival. Maintain at most32 pre-arrival cancellation fences for14 seconds from first admission, without renewal. Fences do not evict active originals. Late cancel cannot kill a successor. Cancel before possible mutation proves not dispatched only for that invocation; after possible dispatch it means unknown. Peer/observation invalidation clears prepared/visible content and leaves any possibly dispatched original outcome unknown; retained status custody may remain only until its fixed deadline on the exact original target. No restoring authority on reconnection/new boot.

## Shared ownership and acceptance
All entry paths acquire MaintenanceIO before invalidation hooks, observer cancellation or producer work. Busy preserves current owner and drafts. Fifteenth-owner integration must preserve all182 existing directed owner relationships and add28 new ones (210 total), with fresh-owner immutable snapshots before await. Enumerate real App call sites, do not substitute a synthetic owner count for actual incoming/outgoing/browser/Electron/observation tests. All current observation quiescence modes must invalidate this lane; this lane must invalidate old preparations without touching another running owner's operation. Capture original outcome/identity/reference before await in both controller and host; validate result and retained-row correspondence against that captured history.

No producer build is needed for consumer fixtures. Use actual Python subprocess/synthetic localhost SSH and actual browser/Electron development/package hosts to qualify framing, fixed selector, EOF, output overflow, termination, late IPC/HTTP and privacy. Synthetic SSH is only a local test seam, not a tablet connection. Reuse current source's qualified Store/CLI semantics at exact provenance; do not rebrand them as this consumer's executed tests. Root owns hosted qualification and actual-main publication. Full task lifecycle remains in one paired delivery.
