## Decisions

Use the same lower-right hold as Reader and note drafting. Recognition preserves the literal current request and identifies a clear request to export a note from the open page. An ambiguous save/export request shows a fixed clarification on the Buddy page without generating or exporting a note. Whole-notebook and circled exports require their own admitted source scopes.

For an explicit request, generate the draft through the installed current-page receiver. Reuse configured destination and actor admission, the existing exact-draft export flow and its readback/recovery behavior. Derive the correlation from the conversation and current-page note scope so repeated saves use the same destination note. An explicit request for a separate note derives a distinct correlation from the admitted submission. Derive the invocation IDs from the admitted submission so a consumed event cannot issue another write. Check source ownership and the draft before export, including the final write gate. Use the existing guarded Buddy-page placement to present the request, draft and result. Describe uncertain outcomes as needing reconciliation.
