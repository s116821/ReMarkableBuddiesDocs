# Source5 stable source witness: assessed precode contract

Main and the existing independent Sol reviewer accepted this separately selected
host observation variant on2026-10-12. It is not yet implemented or
native-qualified, and it does not retroactively qualify57ee. The previous footer
variant remains available explicitly; no failed experiment acquires a fallback.

## Problem and evidence

The actual57ee source snapshots match the selected source5 BODY exactly but lack
the transient Page6of8 UI footer. Archive timestamps place first raw acquisition
about5–6 seconds after positive open-gesture release; the completed response
arrived roughly8.7 seconds after the first postrelease clock sample. Integer
file timestamps do not establish a precise footer lifetime. Removing subsequent
conversion or host decoding cannot recover pixels absent at raw acquisition.

A faster first capture would require preparing fresh artifact/provider checks
before the one GO, capturing immediately after positive release within that
same action, and closing all original identity/sidecar/map/hash proofs before
admission. It would require a new assessed one-use prepared-capture protocol,
including lease, frame/control accounting and ownership checks. Earlier hashes
or unchanged file metadata are not substitutes for required actual-byte checks.

The alternative below retains the selected stable BODY witness and adds an
explicit two-observation conjunction. Its authority remains bounded operator
observation, not atomic native displayed-page identity.

## Two independent source observations

The first completed open snapshot must show exact selected BODY pixels and
provide the full existing candidate boot/PID/start/window/waiting identity,
unclosed admission, fixed stage time, LastOpen document, exact8 ordered page IDs,
source5 content owner and metadata index5, raw sidecar hashes and26 immutable

The first source's raw sidecar hashes must also equal the already retained,

without reducing it to an ID-list comparison. Any raw sidecar change refuses

Compare the approved Library baseline's exact page/context tuple as well as its
raw sidecar pair; only LastOpen changes from canonical Library to selected doc.

The existing full2000ms input-idle pre-arm trigger snapshot is the second source
witness. It must have a strictly later completed remote uptime, its own exclusive

idle observation and all existing publication checks remain mandatory. Two roles
may share the second snapshot, but one frame cannot count as both observations.

Both comparisons must finish within their original immutable response/stage
deadlines. Library is allowed only before the first source witness and only under
the unchanged original pending-Library context/waiting conjunction. After that
witness, Library, mixed/transition pixels, wrong source body, changed raw sidecars,

Record whether the actual transient footer matches in each retained observation

native_current_page_authority=false. Bind these values to validated retained

## Authority and SDK limits

SDK605b validates actual Library readiness, entryForId document identity,
exporting=false, page count, the full idForPage/pageForId map and templateForPage5
before claiming mutation. It does not read an atomic current scene/page-selection
identity; its metadata reports source_authority=false. This draft does not add
such a guarantee. Exact repeated source pixels plus independently unchanged
LastOpen/content/metadata support a narrow display inference on this selected
ordinary fixture. They do not establish production binding/reuse/adoption or a
universal native-current-page API. The previous transient footer gate was also
an operator observation, not atomic native page authority.
This is not a formal equivalence claim: it removes a direct earlier visible
ordinal/footer witness. Identical BODY on another page or stale-but-consistent
persisted current records remain a limitation. The explicitly frozen ordinary
fixture/reference and strict repeated conjunction bound that inference; do not
present it as general production current-page authority.

Native create admission, one-call/one-callback guards, target absence, exact
reconciliation, same-running destination proof, preservation, stop and recovery
remain unchanged. No SDK configuration behavior changes are proposed.

## Existing quotas and timing

Keep the sticky original10-frame/192MiB ledger and existing17MiB control reserve,
25MiB worst-case capture claim, maximum7 worst-case attempts and3 reserved
postcreation frames. Two READY frames plus first source BODY plus full-idle
second BODY consume4 precreation claims, leaving the originally reserved3.
An extra Library/READY/capture failure consumes its claim and can refuse the
selection; no refund, larger quota, third source frame or capture retry is added.
Before the ordinary open input, verify that the remaining shared ledger can fit
both required source captures and all3 protected postcreation claims. Refuse
before input if it cannot, without creating refundable or duplicate claims.

Ordinary capture retains its existing20-second response cap and maximum5 open
frames; navigation capture10/processing2 and all original candidate/SDK/result/
stop/recovery clocks remain unchanged. This proposal improves witness scheduling
without extending any deadline. A locally accepted contract is not native
feasibility proof.
