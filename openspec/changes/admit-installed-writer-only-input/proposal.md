# Why

An ordinary local configuration can enable Writer alone. The installed service still exits when Reader is disabled, even on an RM2 profile that already supports opening a blank conversation and receiving a queued Writer refinement.

# What changes

Admit those two existing gestures through the installed service in Writer-only mode. Preserve the existing behavior on unsupported hardware and in selected or synchronized modes. Add the current-page note action to the same installed service. It takes its input from the open source page and places the Writer draft on the bound conversation page. The existing source-page and continuation submissions are shared by Reader and Writer. The request and context determine the action.

A note from the current page should also work when the user drew their idea. Read writing and drawings together in the existing recognition request. Give Writer both the copied words and a separately identified account of what the drawing shows.

Whole-notebook requests should accept ordinary handwritten RM2 pages made with the stock pens and highlighter. Use the saved pages in notebook order, including their original ink colours and drawings. Keep the pinned paper assets in the saved-source revision and exclude their printed marks from Writer recognition.

Apply the active handwriting profile when reading the original pages of a whole-notebook note, as Writer already does for a note from one page.

An explicit request to save a note from the entire notebook should use that whole source and the configured note destination in one submission. Keep the draft available when the destination is disabled, unavailable or uncertain.

An explicit save of a circled selection should use the same guarded regional draft and configured destination from the shared source submission. Preserve review-first requests and keep the exact source association for a retry.
