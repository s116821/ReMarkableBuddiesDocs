# Installed Writer input

Use the same verified output profile and supervised service as the combined app. A stationary three-finger hold opens or reuses a blank page after all fingers lift. It uses the existing page owner and makes no model request.

For refinement, select a request already queued in the current service activation. Buddy first publishes the complete request under its queue lock, then records the boot-clock second by which it was visible. That second must precede the timestamp of the kernel touch frame that reported the release, on the same clock. A delayed poll or a stalled write cannot attach a new refinement to an earlier gesture. If the input driver cannot supply that clock, the ordinary Reader and blank-start gestures remain available. An older or interrupted refinement without a publication time stays untouched until expiry. A three-second hold started after successful queueing orders the two events.

Immediately before claiming a refinement, Buddy reads the open page and its order again and checks the current draft and conversation. It rechecks the complete request and its expiry under the queue lock. A different page, stale draft or replaced request leaves the slot available. Where the ordinary service also supports generation from the current target, the same corner gesture can select that queued action. Buddy records the activation and request digest at selection and checks both when taking the request for the captured page. The existing queued path leaves Writer-only mode listening when the hold has no queued request. Reader-only mode skips the Writer queue. Shared intent routing supplies the user-facing source action described below.

In combined mode, a valid Reader corner hold still opens Reader if the optional Writer queue cannot be read and the service remains healthy. In Writer-only mode, that case returns to listening. If clock setup loses the first touch frame, discard that new listener and wait for a fresh gesture on a newly seeded descriptor. A later input loss retains the usual failure handling. Keep Reader-only input, history and cancellation behavior. Hardware acceptance uses the installed service, real finger gestures and visible page results.

## Shared submission

The lower-right hold starts shared source intake in combined and Writer-only mode, including when the internal queue has no request. The intake reads the captured image and a bounded recent range from the bound conversation's model context. Included turns retain their original text. Generated drafts that have yet to be published are outside that context, and an over-budget range is refused intact. A reading question proceeds to the existing Reader verifier and answer flow. Writer receives the original request and resolved source scope. A continuation uses the conversation submission key combination. Ambiguous export requests require clarification under the existing destination rules.

## Current-page note

Keep current-page generation distinct from the queued current-target route. When shared intent routing identifies an explicit request for a note about the current page, capture the observed source page with the existing SDK. Use that exact image and its page position for handwriting normalization. Retain the captured document and page in the conversation's source evidence. Honor cancellation during recognition and generation and recheck the page and its order before generation and placement. A blank or unreadable source cannot start note generation.

Use the existing Writer note preset and draft runner. Keep its system instructions out of the visible conversation. Reuse the conversation bound to the source or start one for the captured source. Existing guarded placement opens or reuses the adjacent Buddy page.

## Circled-only note on a fresh source

The same source submission can explicitly request a note from the circled part. Bind the interpreted request and selected geometry to that submission's original capture. Keep the exact request as one Writer turn. The regional runner masks pixels outside the selected geometry before recognition and saves its existing regional provenance and About description with the draft. Place the draft on the verified adjacent Buddy page, including when a fresh one-page notebook needs its first Buddy page. Ambiguous or missing geometry cannot select the current-page path.

## Whole-notebook source admission

The shared hold recognizes an explicit whole-notebook note request and retains its wording. The current installed capture supplies pixels from the open Reader window and samples the document and page order. Those facts alone cannot prove full-page content or supply pixels for the rest of the notebook. The notebook Writer runner verifies coverage of the supplied normalized units. It needs a supported acquisition result for the same notebook with every original source page accounted for in order, including blank pages. Existing Buddy conversation pages must be distinguished from the notebook's source pages.

The receiving path accepts full-page images tied to the current document and its observed native page order, together with the identities of confirmed Buddy output pages. It checks that those two groups account for the entire order and that the request arrived on an original page. It preserves original page positions. The acquisition owner seals the exact ordered PNG digest against the same independently sampled saved-source revision before and after rendering. The saved-source revision binds the document, ordered original IDs, proven blank or present scene state, and the hashes of the scene and layout/template assets used to render. It excludes content of pages whose Buddy ownership has been verified. The receiver checks that the sealed saved-source revision matches the admitted observation and that the sealed image digest matches the supplied bytes before OCR. It records the actual ordered-image digest as normalized-source identity. The owner must reopen and compare saved source through OCR, generation and draft publication. Verified Buddy output content may change without changing the saved-source revision. Any change to native order still requires the existing ownership and order verification. The existing OCR limits apply to the complete set. An unreadable page stops generation. A page with no transcribed text remains in the normalized document as an empty unit. Use the normalized bytes directly with the existing local notebook map/reduce runner and its fresh draft publication checks.

### Saved notebook revision

Reopen the notebook from the service's read-only native store after the caller supplies admitted document/page/order facts, and reconcile the active order through the existing sorted native metadata reader. Exclude only outputs identified by valid ordinary ownership evidence for that document and active order. Hash the saved inputs of each remaining page, in logical order, with the applicable document layout, saved page metadata and resolved template bytes. Unsupported backing documents and layouts, missing scenes without positive blank evidence, and input drift stop acquisition. The source offers a saved revision for comparison independently of raster output. Keep that revision separate from the digest of subsequently rendered images used by the receiver. A later expected Buddy page can appear in native order when its ownership is established and all original inputs still match.

The installed producer interface is `workflow::saved_notebook::acquire_saved_notebook(facts, ledger, deadline, progress)`. `SavedInputs` provides the document UUID, ordered original UUIDs and a hexadecimal SHA-256 revision; `Unavailable` carries the acquisition failure. It samples persisted format-2 notebook metadata, present v6 scene bytes and each original's explicit `cPages` template assignment. The assignment must match an exact safe filename stem registered in the stock inventory. Rows with the same stem resolve to the same files even when their presentation differs. The revision binds the selected SVG and PNG variants, including their presence, without incorporating display names or other registry presentation fields. Positional `.pagedata` rows do not participate in that layout. An original without an explicit assignment stops acquisition, even with a positional fallback present. The producer has no positive blank classifier. A missing scene or an unsupported backing source stops it. The revision alone establishes neither the rendered image digest nor authority to publish.

The rendering pass uses `acquire_saved_notebook_with_pages(facts, ledger, deadline, progress, consume)`. The callback borrows each original page's exact hashed scene bytes, resolved template stem and present SVG/PNG bytes in native order while the file handles are still pinned. It must discard its output on `Unavailable`, including if an input or page ownership changes during acquisition. Revision-only re-observation uses the same reader without retaining raw scene or template bytes.

`SavedNotebookSource::bind_content_revision` supplies `SourceObservation.content_revision` only for an original page of the same document. After rendering, the consumer compares independently sampled saved revisions and uses that same digest in `NotebookSourceReceipt.saved_source_revision`. The separate `NotebookSourceReceipt.ordered_image_sha256` comes from `OrderedNotebookImages::image_digest()`; neither the saved revision nor the observed order is an image digest.

### Bounded saved-scene rendering

Use the pinned `remarkable-rm` renderer for flat v6 handwriting on verified white stock paper. It paints the original tools, colours and overlapping strokes at native scale. Account for each drawable before assembly. Match the tree's layer identifier to its group and visible layer properties. Recognize the standard portrait layout carried by the public RM2 captures as well as the earlier short paper-size record. When handwriting extends below the screen, include the full painted stroke and its edge margin, including wide pen strokes. Unknown layout extensions, unsupported drawing operations, ambiguous paint order, typed text, nonuniform paper or ink outside the supported canvas stop the request before OCR. A verified empty scene keeps its position as a blank PNG. [Pinned renderer and original RM2 pen captures](https://github.com/citizen-stig/remarkable-tablet-cli-rs/tree/544968f002f230ff55c5d438e843aab5a5e9c552/crates/remarkable-rm)

Follow the recorded neighbour links for strokes in a layer and for layers on a page. When several items are ready to paint, take the higher author ID first and the lower sequence number within that author. This preserves the visible colour where concurrent strokes overlap. Refuse a missing neighbour or a cycle before producing an image. [rmscene sibling ordering](https://github.com/ricklupton/rmscene/blob/d7d86ca3a8ca4965d911886a1660bc8acf654c1a/src/rmscene/crdt_sequence.py)

Render one original at a time using the exact pinned bytes shared by the acquisition owner. Admit up to 32 originals within an 8 MiB total retained PNG budget and a 2 MiB per-page PNG budget. Cap scene bytes, block count and canvas per page. Interpret the sealed ordered images for Writer in batches of at most four pages, within the existing byte, pixel and provider limits. Preserve native positions across batches and retain an empty unit for a proven blank. Run the existing notebook planner once on the combined page evidence under its original text, chunk and call limits. A failed or incomplete batch stops the whole request before Writer draft generation. Recheck the independently sampled saved revision after rendering and through the existing ordered receiver. Observe the live resident document, current page and order against the captured visit before provider calls and before accepting results or publishing a draft. Keep the ordinary input, service and cancellation pulse during streaming. Host fixtures verify the accepted scope and refusal paths. Installed navigation and publication require the existing native guards.

When a complete supported acquisition is unavailable, report that complete notebook coverage is unavailable. Keep the present page and existing conversations intact. Context, the open page and a normalized archive whose complete source cannot be verified cannot substitute for the requested notebook. ### Whole-notebook visual evidence

Use a Writer-only page interpretation protocol on the sealed, ordered original images. Each page reply separates verbatim writing from unverified observations of visible drawings, diagrams or image regions. Preserve those parts as distinct normalized sections under the same original page number. Keep the existing notebook planner's bounded ordered coverage and label visual observations in the map and reducer instructions. Historical Reader OCR, handwriting training and pre-existing notebook archives retain their existing protocols.

Treat a fully white decoded original as blank and preserve its original ordinal. A reply that marks a page containing visible marks as blank, a malformed reply, or an unreadable original stops the acquisition before notebook planning. Keep the current image receipt, batches, progress checks and guarded publication path.

Select confirmed handwriting examples once per acquired notebook using the existing profile. Compare each sample's PNG digest against all original PNG digests, including originals in later batches. Label the same reference examples separately from the target pages in each OCR request. Only original-page writing and visual observations enter the note planner. Bind the extractor revision to the selected profile and correction revisions. With no selected examples, use the existing prompt and extractor revision.
