# Design

## One supported declaration
Reuse narrow existing strict saved-document validation, recursively ordered raw serialization and the same conditional Config writer/current ordinary-or-selected custody. Do not add this field to old editor allowlists or change existing wires. Set accepts only the current reference-name grammar without trimming/case conversion. Clear removes the key; omitted and declared-null remain different origins. Clearing declared null changes the raw declaration, while clearing an absent key is a byte-identical no-op. Reject an invalid whole original even if the patch would repair it.

## Private input and original conditions
Names can themselves contain confidential strings; never call them harmless filenames or echo old/new text. Keep original file/path/target/canonical-change digests and intent host-private. The caller retains the exact new change privately for apply; status needs only the original digest-only intent. Hashes are conditional context, not public data or bearer authority. No old-name discovery or filename override is needed to patch a fixed Config leaf.

Inspect/prepare/status read only the explicitly selected Config file, using pure value validation with no declared data/cache/credential-root probes or Store/credential-file/provider construction. Apply alone retains existing Config/Store path-safety metadata checks on all declared roots and their ancestors, including the credentials root, and obtains the existing selected-aware Store and current unconfigured/local/shared/isolated configuration custody before the same mutex/CAS/publication/readback writer. These metadata checks grant no credential-file discovery/content access or credentials-root mutation and must not be weakened or bypassed. Preparation does not freeze mode, grant membership or bind a credential file. Custody remains through one consuming output.

## Truthful saved state
Every operation, including verified apply, reports runtime unverified. A saved reference can point to an absent, unsafe or invalid file; none is inspected here. Existing CLI > environment > protected-file precedence is unchanged. No restart/next-request, authentication, revocation or active provider claim follows from saving/clearing a reference.

A reference edit changes the Config identity used by the separate credential-file protocol. It can therefore make that protocol's original status refuse; this never settles its earlier uncertainty. This source entry has no registry of unknown host invocations. A future host must serialize these lanes, invalidate stale ready grants before I/O, preserve unknown originals and explicitly sequence file removal/install versus reference changes. This producer does not silently combine them or promise atomic two-file setup.

Possible publication/readback/output failure remains unknown, without rollback/retry/rebase/second report. Later status observes desired full Config bytes only, not historical authorship, credential readiness or permission to replay.
