## Exact public capabilities

Public requests are closed objects, maximum384 UTF8 encoded bytes:
- `{action:'inspect',connection_id:DIGEST,boot_id:UUID,invocation:UUID,conversation:UUID}`.
- `{action:'prepare'|'confirm'|'status',connection_id:DIGEST,boot_id:UUID,invocation:UUID,reference:DIGEST}`.
- `{action:'cancel',reference:DIGEST,invocation:UUID}`.
- `{action:'retained'}`: host-memory query only, no helper/target access.

DIGEST means exactly64 lowercase hexadecimal characters; UUID means lowercase canonical nonnil hyphenated UUID. Strict JSON, recursively unique keys, exact types/arity and byte bounds; no coercion, extra fields, selector/path/config/intent/operation/budget arguments. Every invocation UUID is unique for that public action and retained in the reference's bounded invocation ledger. Prepare requires the same host's unexpired inspected reference; Confirm requires its same ready reference. Neither reference is a producer token.

The public result is exactly `{contract_version:1,status:OBS_STATUS,observation:OBS_OR_NULL,conversation_management:VIEW}`, <=8192 UTF8 bytes. VIEW is exactly `{state,reference,preview,report,retained}`. Reference is null for a newly refused Inspect, otherwise the captured request reference or freshly minted reference under the action/state table. Public states: none, inspected, ready, acknowledged, unknown, unchanged, unresolved, not-dispatched, invalidated, capacity, busy, unsupported, unavailable. These are consumer states, not invented producer statuses.

Preview is null except inspected/ready; otherwise exactly `{conversation,turns,source_records,export_associations}` with all counts integer0..4096. Ready values derive from the fresh prepared intent/report, not the older inspect snapshot. Report is null without admitted raw output; otherwise exactly `{operation,status,runtime_unverified:true,local_only:true,physical_reclamation:false,service_observation,possible_effect,current_state}`. The last three fields preserve the admitted producer values and do not confer permissions. No receipt UUID, operation UUID, binding/root revision, intent, digest, Config/actor/generation/roots/path, raw byte buffer, diagnostic or content enters public output.

Retained is <=8 unique rows, each exactly `{reference,connection_id,boot_id,conversation,state,status_available}`. State is unknown|unchanged|unresolved; status_available is a boolean derived from original-byte availability, deadline and invocation capacity, never connection health or success. Only host-issued references are usable; unsupported/unavailable checks preserve the preceding row state. Invalidated idle previews have no retained row. An exact acknowledged response removes that original's private Status grant and retained row after constructing the safe final view; its visible historical acknowledgment/current-state result can remain until normal invalidation. No new operation follows automatically.

An admitted report requires observed matching requested connection/boot. Local-only refusals have unconfigured/null observation/report; producer refusals stay observed reports with their exact status. Busy from failed shared-owner acquisition is distinct from reported producer busy. Public validation cross-checks action, state, reference, preview, report and retained rows, not just each field independently.

The closed public action/state relation is:

| Action | Permitted states | Reference/preview/report relationship |
| --- | --- | --- |
| retained | none | null reference/preview/report; bounded host-memory rows only |
| inspect | inspected,invalidated,capacity,busy,unsupported,unavailable | inspected has new reference, fresh ready report and counts; every other state has null reference/preview, report only for an admitted producer refusal |
| prepare | ready,invalidated,capacity,busy,unsupported,unavailable | same requested reference; ready alone has fresh prepared report/counts; refusal has no preview |
| confirm | acknowledged,unknown,unresolved,not-dispatched,capacity,busy | same requested reference; no preview; acknowledged requires exact receipt admission, unknown/unresolved require corresponding retained row; true-effect conflict reduces to unknown |
| status | acknowledged,unknown,unchanged,unresolved,capacity,busy,unsupported,unavailable | same requested reference; no preview; unknown/unchanged/unresolved refer to the original retained row; reported refusal preserves preceding row without settling it |
| cancel | invalidated,not-dispatched,unknown,unchanged,unresolved,unavailable | same requested reference; no preview/report; only exact invocation can affect its current grant/child; previously retained state survives |

For every report, operation equals inspect/prepare/apply/status for the corresponding public action; retained/cancel never have a report. Local unknown after loss has null report and a retained unknown row. Host stale/transport/parse failures after possible Apply dispatch always use unknown regardless of whether a lower-level adapter labels the failure unsupported or unavailable. Refusal to launch a new Confirm while another owner is busy preserves the unconsumed ready grant privately; no public Busy response itself renews or replaces that grant.

No caller-controlled command text or alternate route. Send the validated exact input bytes then EOF. ## Strict intent and raw report admission
Read one strict UTF8 JSON object <=32768 original bytes including exactly one terminalLF and no other literalLF. Fatal UTF8, BOM, recursive duplicate members, partial/multiple reports, extra keys, malformed integers/bools, noncanonical identifiers and trailing JSON refuse with static errors. No sorting, truncation, normalization or cached-safe fallback. A positive safe-integer future report version is unsupported; malformed version/current report is unavailable. After Confirm has crossed possible dispatch, any such refusal preserves local unknown and its original.

The report has exactly13 fields: report_version, operation, status, runtime_unverified, local_only, physical_reclamation, service_observation, possible_effect, conversation, intent, receipt, current_state, summary. Require version1, matching selector, runtime_unverified/local_only true and physical_reclamation false. Service is inactive|unverified; current_state is null|live-original|desired-tombstones|changed. Nullable conversation must match the selected/original conversation whenever present. Null means unobserved, never a different target or absent conversation. Summary is null or exactly three bounded integer counts. No new field is forwarded.

Intent has exactly14 fields in canonical order: intent_version:1, operation, conversation, config_path_sha256, config_bytes_sha256, roots_sha256, actor, generation, mode_sha256, target_history_sha256, root, binding, summary, intent_sha256. Root is exactly `{revision,sha256}`; binding is null or `{id,revision,sha256}`; summary is exactly `{turns,source_records,export_associations}`. Validate all UUIDs/digests/counts and exact hash: SHA256 of UTF8 `RMB-CONVERSATION-DELETE-V1\n` followed by compact JSON of the first13 ordered fields, including explicit binding:null, no trailing LF. Nested field order is the displayed producer order. Config path digest is SHA256 of exact UTF8 fixed Config path, not the cache-cleanup framing convention. Original Config bytes/roots/mode/history hashes stay opaque; Manager does not read/reconstruct them or assert their authority. Bind prepared operation/target/summary to host context and the top-level report.

Receipt is null or exactly `{operation,transaction,root_revision,binding_revision}`. Acknowledgment requires operation equals original operation; transaction/root_revision match UUIDv5(NAMESPACE_URL, `urn:remarkable-buddies:conversation-cleanup:v1:{operation}:{role}`), roles transaction/root-revision. Binding revision is null for an unbound original, otherwise the derived binding-revision UUID. Recompute only these deterministic identities from the stored valid intent; never invent or persist a receipt, inspect native state or treat a tombstone alone as acknowledgment.
