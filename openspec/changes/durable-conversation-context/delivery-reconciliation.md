## Complete production behavior

The candidate contains the original unbound Orchestrator/Ledger composition,
historical legacy/development capture records, selected historical context and
binding inspection, and fact-only attempt outcomes. Main constructs Orchestrator
with the shared Ledger. A prepared iteration persists its acquired source batch
before either model call, reopens those exact bytes for both passes, persists
interpreted request and generated draft facts, and records uncertainty before
navigation/output. Failed durable preparation prevents provider/output dispatch.
Unverified output remains ReconcileRequired rather than becoming Completed or an
automatic retry. These are actual runtime changes compared with current main;
constructor compilation alone does not qualify them.

Analysis and independent-verification prompt literals are byte-identical to
the incoming current source. The LLM implementation, transport, credentials,
model settings and request cancellation module are unchanged. Image delivery
changes from querying detail images for each pass to one acquired ordered batch
whose exact stored bytes feed both passes. Thus it adds durable custody and
prevents a second detail query; it does not invent a new prompt or model backend.
The changed-candidate recording-provider test checks two actual Orchestrator
calls with identical image arrays, exactly one detail acquisition, unchanged
source pixels, reopened outcomes and no reconstructed model/device effects.
Other focused controls cover preparation/provider failure and SDK acquisition
failure without fallback or dispatch. This is scripted host evidence, not a new
live-provider result. No earlier model result is promoted to this candidate;
this document supplies no new provider credentials or model choice.

Private selected execution context minting, attachment and dispatch remain
`cfg(test)` under the accepted runtime compilation boundary. Ordinary runtime
has no qualified selected-source adapter/bootstrap and cannot reconstruct native
authority from stored facts. Read-only selected inspection remains compiled;
unbound, stale, omitted or mismatched data keeps its existing refusal. Development
captures remain explicitly unqualified, and historical binding inspection is not
page selection, native freshness, insertion or successful output.
