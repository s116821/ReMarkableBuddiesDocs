## Frozen output and reading boundaries

Output is one compact JSON report: `report_version: 1`, operation (`startup`,
`inspect`, `context`, `recover-pending`), fixed status, `incomplete`,
`native_authority: false` and optional `data`. Status values are `complete`,
`historical`, `not-found`, `choice-needed`, `unsupported`, `busy`, `unavailable`
and `invalid-input`. Startup unsupported data contains the fixed SDK reason
`no-native-adapter`; no SDK Debug string or invented native profile is used.
Context without a real tokenizer reports choice-needed and no model-ready data.
Inspection returns bounded historical records plus explicit snapshot provenance,
never a native current-page claim. Recovery returns only the original validated
receipt/reference and historical publication identity, not a live token.

Unknown original operation maps to not-found without allocation or publication.
Known original operation with changed request/pins maps to invalid-input;
missing/corrupt original lineage maps to unavailable. Do not classify errors by
matching arbitrary parser/user text. Use a narrow typed existing recovery result
where needed rather than weakening historical request validation.

Current inspection uses `selected_snapshot_with_budget` and the existing shared
ordered admission through the actual writer; payload and token/raw-custody pins
are sealed. The Store lease survives processing return. Stale/exhausted/altered
admission emits fixed unavailable/no data before a write; partial I/O failure
never attempts a second report. The one receiving allowance is 64 snapshot
attempts/4096 work/8 MiB metadata/32 MiB verified media, including final rechecks.
Startup/normal Store opening, provider work and generic publication are outside
that allowance. Existing historical-first recovery reads original history/objects
under its independent existing Store bounds; it does not inherit the cumulative
snapshot cap or become current authority. Do not duplicate the generic validator
or claim a combined full-command I/O/latency cap.
