## ADDED Requirements

### Requirement: Installed selected Reader prepares exact historical input

The selected resident Reader SHALL admit both verified registered pure
Conversation and mixed document closures. It SHALL validate the exact captured
document and publish the root, Prepared turn, Source schema2 evidence, all
required media and original receipt in one conditional selected transaction.
Only a fresh exact readback SHALL feed the existing selected Reader receiver.
An uncertain or stale publication SHALL allow only original historical
recovery and SHALL NOT replay the capture, admission or model request.

#### Scenario: Pure and mixed registered custody

- **WHEN** the exact current registered document has either supported closure
  and the resident capture matches it
- **THEN** its complete original and derived media remain linked to the exact
  Prepared turn and any unrelated document memory remains unchanged.
- **AND** a missing, stale, foreign or unreceived registration refuses without
  ordinary publication, registration or a model call.

## MODIFIED Requirements

### Requirement: Selected request and draft publication

Selected interpretation and Generated drafts SHALL use canonical selected
admission, exact acknowledged root/user references and preserved evidence.
Failed publication SHALL stop without an ordinary write or later effect.
An acknowledged Generated draft SHALL leave Pending, settlement and native
output unavailable.

The installed resident Reader SHALL retain the original effective preference
and canonical selected custody through every actual submission and result
publication, joining optional selected memory as applicable. It SHALL use one
cumulative bounded request across analysis, verification and optional
enrichment, and preserve exact original-only recovery independently of fresh
admission.

#### Scenario: Original request remains valid across multiple bounded calls

- **WHEN** the unchanged installed Reader request takes more than a one-stage allowance while
  remaining within the original selected Reader deadline and reservations
- **THEN** the existing model stages may complete using the original pins,
  and exactly one selected Generated result publishes without a new budget,
  fallback, or device effect.

#### Scenario: Draft acknowledgment lost before retry
- **WHEN** the same operation and original input are retried after an acknowledged selected draft publication
- **THEN** the original receipt and pins SHALL be recovered before stale-head checks. The selected history SHALL contain one draft and no new live authority.

#### Scenario: Prepared preferences retain currentness
- **WHEN** a prepared request uses a personalization preference and the selected view changes during that model call
- **THEN** the changed selection SHALL refuse Generated publication. Unsupported or foreign subject-memory providers SHALL refuse before query or model work. An explicitly compatible selected Provider MAY enrich only through the sealed selected-memory path and joined publication; it SHALL NOT bypass currentness or grant native authority.
