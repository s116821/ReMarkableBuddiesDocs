# Bounded investigation and qualification matrix

Native creation/lifecycle rows below remain NOT RUN. Separate bounded SDK R1/R2/R2D observations do not qualify insertion or activation. Record candidate/commit/build, exact firmware/xochitl/Qt/architecture, fixture/operation IDs, hashes, timings, outcome, logs and visually inspected screenshots. Distinguish source inspection, offline fixtures, simulator, native and live-model evidence. Page mechanics need no model call.

Each experiment records deadline/abort condition before execution. Start with one discovery pass and one smoke per candidate/fixture; only candidates passing integrity/identity gates advance. Permit one evidence-driven correction per failed probe, then review remaining concrete hypotheses with coordinator before extending the bounded plan. A timebox stops that probe, not the automatic requirement. Continue credible unresolved alternatives. Do not execute a demonstrably unsafe mutation merely to tick a box: record static barriers and test the safe reduced claim. Final fallback still needs actual viable-candidate and manual-path tests, not an all-static matrix.

## Outcome record required during implementation

For A-E record exact method/signature, versions/firmware, notebook and open-PDF outcomes, preservation/persistence/retry/cancel results, blockers, correction attempted, and accept/reject rationale. Link native evidence and regressions. Include searches and unresolved leads: untested is not failed. Independent reviewer checks exhaustiveness. Automatic acceptance records exact supported envelope. Fallback acceptance records exercised setup, limitations and revisit triggers (new method, resolved ABI/lifecycle support, safe cache coordination), plus REM35 decision.
