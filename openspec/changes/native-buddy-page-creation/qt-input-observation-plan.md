## Smallest specialized protocol and publisher reuse

Keep existing facts-request/read-facts and publisher behavior unchanged. Add one
fixed purpose-specific observation-end publisher entry using the existing
descriptor-safe routines, immutable waiting identity, locked ownership and
exclusive temporary/final publication algorithm. It accepts only the existing
fixed root/nonce/expected PID/start argument shape, never an arbitrary command,
stage, filename or payload argument. Its specialized entry binds exactly the SDK
input-observation-ready/end filenames and stage/profile. No generic command router
or generalized broker is introduced; a read-facts token cannot invoke this mode.

Successful end publication proves only a durable token, not event delivery, GUI
execution, image completion or page facts. Unknown publication retains evidence
and selects no replay. No PageFactsSession, native OPEN, Qt synthetic input or
controller operation is issued by this diagnostic.

## Prospective Main-only recipe and collector

Reuse existing reviewed startup/root/nonce/attempt/stock recovery machinery and
the source-only guard for any future private specialization. The fixed operator
observes the SDK diagnostic-ready marker only after exact root inode/owner,
attempt PID/start/executable/maps, live service/empty job and unclosed stage checks.
Main may then perform zero or one separately selected source-bound echo action;
no observer/capture failure authorizes another input. Main publishes observation
end exactly once after that action or explicit zero-action control.

Collect the distinct bounded completion JSON and optional Qt window PNG with
exact file type/mode/owner/size, scope/hash and live generation checks. Do not run
facts proof validators or set facts success flags from observation completion.
Record actual GUI completion, bounded counts/overflow, target-window relationships
and image availability separately. Failed/partial/late/missing marker/image or
changed window is inconclusive. Restoration and historical-only collection remain
mandatory; historical artifacts never upgrade live flags.

Original host150000ms starts BEFORE arming; setup120000ms starts at entry birth;
completion5000ms begins only at valid end acceptance. Rollback initiation180s and
restoration TimeoutStart240s remain distinct. No extension, reset, added pacing,
automatic publication or action retry. The accepted one-total read-only status
timeout allowance may apply only to this specialization's initial completion
status poll after explicit source review, with identical exception/deadline rules;
it grants no extra image/end-publication/generation-operation retries.

Main obtains separate existing heap capture and, if separately selected, physical
evidence. A Qt image may render/read back and is not passive or hard cancellable.
Keep capture order/timestamps and window stability explicit: an image difference
is attribution/coherence evidence only with adequate temporal alignment, not proof
of physical EPD behavior or a handler's acceptance. Event records describe an
observer delivery boundary, never unique physical contact counts or kernel cause.
