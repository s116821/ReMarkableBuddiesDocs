# Declared model credential protocol v1 (unimplemented)

## Entry and limits
`--model-credential-operation inspect|prepare|apply|status` is independent of every runtime/maintenance operation. Inspect accepts no input selector and never reads stdin; all other operations require exact `--model-credential-input -`, strict EOF-delimited UTF8 JSON and no file fallback. Refuse other runtime/maintenance flags before dotenv, environment credential resolution, logging, provider, worker or service initialization. `REMARKABLE_BUDDIES_CONFIG` must name one explicit absolute existing regular config. No default, caller filename/root or reference override.

Request and single-LF report each cap16384 bytes including whitespace/LF. Config/existing credential files each cap1048576 bytes. New decoded secret text caps8192 UTF8 bytes and must be nonblank under the existing trim-only emptiness check; preserve all accepted decoded bytes, including CRLF, controls and trailing contents, with no appended file LF. This maintenance cap does not change existing resolver limits or key-format validation. Existing protected file bytes need not decode as a usable key to be deliberately removed/replaced. No old bytes are returned.

All objects below are exact records with recursive unknown/duplicate refusal, no positional arrays, coercion or implicit nullable fields. Version is1; operation UUID is nonnil; HASH is lowercase64hex. Unknown versions report unsupported. Non-Linux targets report unsupported before stdin/config/credential access; no privacy fallback.

## Path, privacy and file admission
Strictly validate complete original Config declarations, then resolve only current `paths.credentials/model_credential` using the existing name grammar (1..80 ASCII alphanumeric, hyphen, underscore). Missing reference is unsupported. Do not use resolve/Environment, read another credential, create a root, rewrite Config or materialize defaults.

Require an existing exact0700 credentials directory owned by the current effective uid/gid, no special mode bits or symlink/reparse ancestors. Config and credentials root must be disjoint. Credentials must be lexically disjoint from data/cache for every operation; apply additionally checks canonical disjointness against all owned roots before any staging. Read-only operations canonicalize only the credential/config paths and do not probe declared data/cache roots. Refuse unsupported required alias checks. Config itself cannot be the target or an alias of it. Existing credential must be a regular file, one hardlink, same effective uid/gid, exact0400 or0600, no special bits, unchanged path-versus-open metadata and bounded bytes. Refuse unsafe files/permissions rather than chmod/chown repair. Preserve original file mode on replacement; install uses0600. Parent/owner requirements are narrow capability admission, not a change to the general resolver's accepted files. Apply validates all owned roots/current existing Store additionally; read-only operations do not open data/cache roots or a Store.

Secret text AND content-derived hashes are confidential. An unsalted digest can support offline guessing and MUST NOT be described as non-sensitive. Every BINDING/INTENT below is private maintenance transport, never public renderer/log/telemetry/error material. Do not Debug/log requests, raw reports, existing bytes or parsed secrets. Public reduction is limited to operation/status/outcome/presence/disk verification/runtime-unverified; a future host must separately specify private memory lifetime and safe DTOs before consuming this producer. Public tests/examples contain explicitly synthetic credentials only. No real intent belongs in a repository or diagnostic attachment.

## Fingerprints and exact records
Config SHA covers complete original bytes. Path SHA recipes are SHA256(UTF8 prefix + exact absolute UTF8 path): `urn:remarkable-buddies:model-credential-config-path:v1:` and `urn:remarkable-buddies:model-credential-file-path:v1:`. The latter is the resolved original credential path; neither path/string/reference is echoed.

Metadata recipes are SHA256(UTF8 prefix + recursively string-key-sorted compact UTF8 JSON, no LF). Prefixes are `urn:remarkable-buddies:model-credential-parent:v1:` and `urn:remarkable-buddies:model-credential-file-metadata:v1:`. Parent metadata has exactly device,inode,uid,gid,mode; file metadata adds links,length,mtime_seconds,mtime_nanoseconds,ctime_seconds,ctime_nanoseconds. Every value is the canonical decimal string of the corresponding Unix metadata value (no leading plus/zeros, minus only for signed negative timestamps). Mode includes the full metadata mode. Parent mtime/link count are deliberately excluded: unrelated sibling changes are not parent identity changes. Independent synthetic vectors must pin both recipes.

STATE is exactly `{kind:"absent"}` or `{kind:"present",sha256:HASH,metadata_sha256:HASH,mode:256|384}` (0400/0600 decimal). BINDING is exactly `{config_sha256:HASH,config_path_sha256:HASH,credential_path_sha256:HASH,parent_identity_sha256:HASH,state:STATE}`. Absence is explicit, never a null hash or empty-file synonym.

CHANGE is exactly `{action:"install"|"replace",value:STRING}` or `{action:"remove"}`. Install requires absent original; replace requires present original; remove of absent original is a no-op. Replacement of exactly the original bytes is a byte/permission-identical no-op. Install against present or replace against absent is conflict, never an implicit conversion.

DESIRED is exactly `{kind:"absent"}` or `{kind:"present",sha256:HASH,mode:256|384}`. INTENT is exactly `{credential_version:1,operation:UUID,base:BINDING,action:"install"|"replace"|"remove",target:DESIRED}`. Action/base/target must be coherent: install absent->present0600; replace present->different content with same mode; remove present->absent. No-op has no intent. Intent contains no secret text but remains confidential because its hashes are secret-derived.

## Operations
Inspect has no request; success DATA is exactly `{schema_version:1,binding:BINDING}` after one bounded admitted observation. It does not prove a usable credential/provider/runtime.

Prepare request is exactly `{credential_version:1,operation:UUID,base:BINDING,change:CHANGE}`. Reobserve the original config/path/root/file and compare EVERY base field; never refresh/rebase. Validate change/action and compute target without writing, opening a Store or resolving a provider. Changed success DATA is `{intent:INTENT}`; no-op success DATA is `{binding:BINDING}`. The caller retains original secret CHANGE privately, separate from intent.

Apply request is exactly `{intent:INTENT,change:CHANGE}`. Compare action and exact decoded target hash/mode, revalidate original bindings and full Config, acquire existing ordinary-or-selected configuration Store/current mode custody, then recheck original config/root/file conditions under the SAME Store mutex used through publication and readback. No initialization/repair/domain constructor, fallback, mode switch, reference edit or second writer. Preparation did not freeze mode or grant membership. Hold Store/mode custody through the single consuming output attempt.

Seal an exclusive private sibling stage and fsync it before install/replacement. Preserve original permitted0400/0600 on replacement before sealing; stage ownership must match admitted uid/gid. Install must publish without replacing any destination; a sealed-stage hardlink followed by removal of only that owned stage is permitted. A newly race-created target survives. Replacement uses atomic rename of the sealed stage. Remove unlinks only the admitted original. Sync parent and verify exact desired absence or bytes/private ownership/mode/link count before complete verified output. No config/cache/data/history mutation or general cleanup. This serializes cooperating Buddy writers under owned-root exclusion, not hostile same-user external writers; do not claim a filesystem-wide compare-and-swap primitive.

All checks/staging faults before attempting destination link/rename/unlink are known not-dispatched. From the destination syscall attempt onward, errors/faults, parent-sync or readback failure are failed/unknown even if a particular injected case is known not to publish. Never rollback, reapply, delete the target or emit a second report after partial output. Only this attempt's checked sibling may be cleaned; unsafe/unknown leftovers are retained rather than recursively swept.

Status request is exactly `{intent:INTENT}` with no CHANGE/raw secret. Validate intent, reread original Config and original parent/path bindings, then only the original credential file. Config/reference/root change refuses; do not follow a newly configured target. Desired-present requires exact target hash, mode, current effective owner/group and link count1; desired-absent requires actual absence under the unchanged original parent. Success desired observation DATA is `{present:BOOLEAN}`; a different admitted file/state gives unresolved/null. No Store/mode/provider probe, write or original-publisher/history/effective-authentication claim. A missing/unsafe/unreadable prerequisite refuses and never settles prior uncertainty.

## Reports and uncertainty
Exact report fields: `{report_version:1,operation:OP,status:STATUS,outcome:OUTCOME,disk_readback_verified:BOOLEAN,runtime_activation:"unverified",data:DATA_OR_NULL}`. STATUS is ok,invalid-input,unavailable,unsupported,busy,conflict,failed. Outcomes are read-only,prepared,no-change,verified,desired-file-observed,unresolved,not-dispatched,unknown. Inspect success uses read-only; prepare changed/no-op uses prepared/no-change; apply success uses verified/true DATA `{present:BOOLEAN}`; status desired uses desired-file-observed/false; unresolved uses null/false. All refusals use null/false and read-only for inspect/status, not-dispatched for prepare/apply unless publication may have been attempted. Possible publication uses failed/unknown/null/false. Every report keeps runtime unverified.

Saving/removing a file does not change CLI/environment precedence, revoke an environment/provider credential, reload a running process or verify authentication. Missing/truncated/cancelled output stays unknown; explicit status is a present-state observation, never historical settlement, permission to replay or proof the previous save did not happen. Encoding/bounds precede one consuming write. No error includes raw paths, references, secret text, fingerprints or backend error strings.

## Required evidence
Pin independent path/metadata/secret synthetic digest vectors. Actual Unix CLI install missing/replace/remove/no-op and original conditions, exact Unicode/CRLF/trailing bytes and untouched sentinels; one-hardlink/symlink/root/config aliases; private-mode/owner refusal and preserved0400/0600; no-clobber install race; same-mutex config/file changes; all four existing ordinary/selected current modes/Busy; before-publication and post-attempt replacement/removal/sync/readback faults; consuming prefix with actual ownership held; strict shapes/duplicates/EOF/caps/flags; source resolution/precedence/archive behavior unchanged. Capture only synthetic exact reports with clean build/executable provenance. Non-Linux must prove early unsupported/no access, not pretend its fixtures establish Unix permissions. Future browser/Electron private buffers/reduction/transport are separate. No real credential, provider or tablet action follows.
