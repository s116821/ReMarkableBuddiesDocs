## ADDED Requirements

### Requirement: Private intent and read-only desired-file reconciliation
The host SHALL retain original base/path/target evidence privately before one apply dispatch and SHALL expose only a reduced safe view/opaque reference. Status SHALL only observe exact original target bytes and SHALL NOT prove historical publisher identity, refresh conditions, mutate or settle uncertainty from later command refusals.

#### Scenario: Lost apply report
- **WHEN** apply may have run but its complete verified report is unavailable
- **THEN** original evidence remains unknown and explicit status can report desired-file-observed only for exact prepared target bytes without replaying apply.

#### Scenario: Fresh deliberate edit after an unknown outcome
- **WHEN** the user explicitly begins a distinct edit from fresh current state
- **THEN** it has new conditions/reference and preserves the prior diagnostic without claiming rollback or evicting unresolved evidence at capacity.

### Requirement: Shared explicit editor with preserved session lifetime
Both browser and Electron SHALL offer the same three-field saved editor using protected fixed host adapters, no-saved-override choices, truthful origins and neutral pending/readback status. Before-I/O external invalidation, original receiver, serialized cancel and after-await generation checks SHALL preserve ready/unknown references and unrelated memory-forget uncertainty.

#### Scenario: Refresh or navigation races a save
- **WHEN** cancellation, same-ID refresh, real document navigation or target change occurs
- **THEN** ready references and late views are invalidated while possibly dispatched original apply remains unknown with no repeat.

#### Scenario: Saved preference versus running behavior
- **WHEN** a disk save or desired-file observation succeeds
- **THEN** both hosts show its exact limited saved-state result without service/provider checks, automatic restart or effective environment claims.

### Requirement: Strict fixed protected consumer contracts
Both hosts SHALL validate exact bounded public requests/reduced results and complete private producer phase reports, retaining original private target linkage without exposing Config, hashes or intent. Fixed wired operations SHALL preserve current authorization, before/after identity and deadline hierarchy. No arbitrary operation/file/service fallback is allowed.

#### Scenario: Public injection or malformed projection
- **WHEN** extra/duplicate/raw/private fields, unsupported versions, malformed types/origins or bounds reach a public bridge
- **THEN** the entire request/result refuses before unsafe dispatch or renderer publication, without coercion or partial success.

#### Scenario: Private phase mismatch
- **WHEN** before/after fields, original operation/base/path/changes, target hash, status/outcome/readback or activation disagree
- **THEN** the private result refuses and any possibly dispatched original apply remains unknown rather than retried or relabeled no-write.

#### Scenario: Startup or late client refusal
- **WHEN** a complete startup/status result cannot be parsed or a final result arrives after generation/identity changed
- **THEN** neither host nor UI restores ready/verified authority and original uncertain evidence remains separate from the failed invocation.

### Requirement: Deliberate bounded three-field save
The shared editor SHALL expose only three supported finite fields and origin-aware set/clear with dirty keys. One120s ready grant permits at most one prepare/apply under one existing13s budget. One active slot and at most8unresolved original records SHALL remain bounded without eviction or condition refresh.

#### Scenario: Explicit null or unchanged field
- **WHEN** a declared-null field is deliberately cleared or another field is left untouched
- **THEN** clear removes that declaration while untouched keys stay absent from the patch and default/null origins remain truthful.

#### Scenario: Duplicate save or phase budget expiry
- **WHEN** Save repeats/concurrently claims a reference, or its single budget expires between prepare and apply
- **THEN** at most one apply may dispatch, none starts after expiry, and before-versus-after possible dispatch yields honest not-dispatched or unknown state.

#### Scenario: Capacity or stale cancel
- **WHEN** eight unresolved originals occupy capacity or an old reference is cancelled while newer work exists
- **THEN** a new write refuses without eviction/dispatch and the old cancel cannot kill or replace the newer operation.

### Requirement: Attributed paired verification and own lifecycle
Consumer acceptance SHALL use original producer bytes/capture identity separately from synthetic faults, retain real guarded browser/Electron paths and both ordinary OS package jobs, and complete only this consumer's canonical sync/archive in its linked delivery.

#### Scenario: Native report corpus compatibility
- **WHEN** original45captured reports are accepted as fixtures
- **THEN** exact stdin/stdout hashes and typed phase/projection linkage verify without replaying producer executions or claiming induced transport loss/native runtime evidence.

#### Scenario: Final shared delivery
- **WHEN** the editor is proposed for normal merge
- **THEN** current both-OS checks, responsive UI inspection and independent review pass, own canonical/archive match implemented scope, and actual-main/publication remain separately observed.

#### Scenario: Older status versus active or ready editor
- **WHEN** explicit status checks an old diagnostic while a newer Save owns I/O or a distinct editor grant is only ready
- **THEN** it respectively refuses busy without cancelling newer work, or acquires the single slot and invalidates ready before remote I/O, preserving original uncertainty and conditional owner release.

#### Scenario: Older forget cancel versus newer settings save
- **WHEN** a retained old forget reference is cancelled while a distinct basic Save owns the observer
- **THEN** targeted lane/reference/token ownership prevents raw cancellation or cross-invalidation of the new Save, which may complete once, while old forget evidence and original receipt bytes remain unchanged through both guarded hosts.
