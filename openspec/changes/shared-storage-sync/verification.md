## Retention and external boundaries

Failed ordinary write attempts remove only their own temporary file. Under the exclusive lease, reopening removes exact `.stage-<UUID>` names in validated runtime/current-generation directories. Content-addressed incoming objects deduplicate repeated downloads. Immutable orphan content and old generations are retained for deliberate recovery/retention policy; there is no destructive collector. A failed external export may leave a destination without `backup.json`; it is incomplete and must not be treated as a backup.

Windows host tests do not prove Linux directory durability. Linux ARM emulation proves tested OS behavior under emulation, not tablet storage/power-loss behavior. All records/media/grants are synthetic; HTTP tests use localhost or an in-memory transport. No live account, consent, upload, tablet, firmware/reset or live-model operation was performed. These limits do not waive REM-35 or any later feature's native/live validation requirements.

Conversation/domain schemas and convenient read-only namespace enumeration remain REM-37; memory and handwriting behavior remain REM-24/26; the device-local executable native-operation journal remains REM-25. Credentials grant UI, host transport and companion controls remain REM-41/42. No release files or workflow scaffolding are part of this implementation scope.
