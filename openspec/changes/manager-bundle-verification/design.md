# Design

## Contract and ownership

Pin actual Manager publisher release/coordinator.py and policy.py at accepted bf13a9015c294b591c94de15490cf9e291a9c20e; those files remain unchanged and Main/REM-46 owned. Current targets browser, win32-x64, linux-x64 yield manager-browser.zip, manager-win32-x64.zip, manager-linux-x64.zip plus provenance.json. Manifest fields tag/sha/version/packages and completion manager-complete with provenance_sha256 match the existing publisher. Every ZIP has root build-info.json with exactly version/sha/tag/official, true official and tag-derived version/source. Dependency/tool versions are not project version authority.

Use a closed literal Manager profile in the accepted host quarantine engine: fixed s116821/ReMarkableBuddiesManager APIs/HTML/download URLs, stable explicit annotated tag directly to commit, exact assets and completion/server/provenance identities. Caller remote URL/repository/filename overrides remain unavailable; accepted Buddy wrapper/receipt and refusal controls remain supported. Existing JSON/redirect/deadline/stream/aggregate/local path/exclusive write/publication recheck/staged hash/atomic cancellation boundary are reused. No source switch or new tablet admin API.

## Bounded archive observation

After actual digests match, invoke a fixed local verifier script through explicitly selected absolute Python3.12 runtime, -I/-S/-B, allowlisted environment, bounded stdout/stderr/time and shared cancellation. No script comes from ZIP contents; subprocess executes trusted checkout code only. Manual command is source-checkout tooling, not a packaged updater or new renderer capability. Public Python prerequisite is explicit; no global install.

Reuse the unchanged pure producer verify_identity contract after bounded observation of all exact local files: canonical regular nonlinked files, exact inventory and sizes/digests bracketed; strict duplicate-aware bounded manifest/build-info JSON. ZIP files max512MiB, aggregate768MiB; current format must have final22-byte EOCD, no ZIP64/comment/multidisk, at most4096 entries and central directory at most2MiB before stdlib ZipFile opens it. Then reject duplicate/unsafe paths, links/special files, encryption/unsupported flags/compression, unexpected metadata and excessive entry names/extra/comment fields. Only root build-info.json is decompressed, max16KiB; total declared expanded bytes bounded2GiB. Payloads remain unexecuted/unextracted and their individual semantics/CRC/native safety are not claimed. Preflight uses Python stdlib struct/zipfile, not another archive engine; module code hashes of unchanged producer/policy are qualified before import, future changes refuse until coordinated requalification. Isolated Python excludes ambient import/config/credential hooks.

Compare strict embedded identity to fixed tag/peeled source and provenance, then use the unchanged pure producer identity validator. Independently hash each actual ZIP through its bounded open handle before metadata observation and bracket its identity. Do not invoke producer verify_packages, whose unbounded pathname rereads are unsuitable for downloaded input; strict metadata and ZIP observation use the standard library against the actual bytes instead. Verify process returns only a bounded fixed result; raw diagnostics/archive text never enter receipts. Hash staged files and recheck publication after archive observation before final commit. Directory and source files can be bracketed, not guaranteed atomic against malicious same-user writers. Failure leaves incomplete quarantine without completion; never deletes user files.

## Outcome and verification

Manager receipt states actual checksum and embedded identity agreement, opaque staged ZIP bytes, installation/update eligibility false, no independent signature/compiler/native qualification and fresh revalidation needed for later use. It does not install, unpack app files or start code. A readable embedded declaration is not an attestation of build truth. Existing Buddy receipt remains APK-ineligible.

Meaningful tests use actual HTTP/file bytes and actual Python ZIPs produced by the existing archive function. Cover success/cross-repository rejection, missing/damaged bytes, malformed/duplicate/contradictory build-info, ZIP metadata bombs/inventory/link/path/format refusal, interpreter/timeout/cancellation/sanitization, late atomic-commit boundaries and unchanged Buddy controls. Label supplied fixtures versus live official release/native evidence. Required supported Node/Python Linux/Windows CI, linked exact Docs/code and existing independent reviewer precede delivery. No new worker/checkout. Canonical sync/archive and parent-first merge remain coordinated; don't archive other lanes or claim full REM-41/46 completion.
