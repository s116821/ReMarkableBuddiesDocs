Config.personalization defaults to {schema_version:1,enabled:false,text:""}. Version1 accepts UTF-8 text at most16384 bytes, including CRLF, Unicode and leading/trailing whitespace; NUL refuses. Disabled text is retained, clear resets text and enabled, and empty text has no effective preference. Debug output redacts text. Preference does not encode authority, source content, history, learning or operation grants.

CLI --personalization-operation inspect|set|disable|clear runs before environment credentials/model/device startup. Explicit REMARKABLE_BUDDIES_CONFIG selects an existing whole config. Inspect requires no stdin. Other actions accept strict bounded JSON on stdin (at most131072 bytes): contract_version1 and expected_config_sha256; set additionally requires enabled and text. No text is carried in argv. Exact full-file digest binds the mutation. All unrelated typed config fields are preserved.

Mutations use existing owned Store preflight(false), Store::open's stable OS lease and Store::replace_config's existing revision check/atomic write. Missing/unsupported/active stores refuse without initialization. Existing maintenance stop-confirm-lease protocol applies. No new writer/lock service is invented. Disk readback revalidates the full Config and checks the published digest/setting; uncertain postcommit failure is not rollback evidence. This is not atomic against hostile same-user writers.

Reports expose text only for the explicit editor readback, never routine logs/errors. Success reports disk_reload_verified:true, config_sha256, personalization and runtime_activation:"restart-required". A one-shot readback is not proof of the running application adopting the file. Manager must separately stop/restart and verify runtime activation using the applicable OS/runtime contract before reporting active. The validated immutable snapshot accessor supports a next-request boundary: existing snapshots are unchanged by later edits/reloads. Receiving Reader/Writer application, exact transcript forwarding/precedence, live provider and selected sync policy remain unfinished REM-53 work.
