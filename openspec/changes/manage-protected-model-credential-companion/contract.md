# Protected model-credential companion (unimplemented precode)

## Authority and exclusions
Unchanged [canonical producer](../../specs/declared-model-credential/spec.md) and [exact archived contract](../archive/2026-10-22-manage-declared-model-credential/contract.md) define confidential records, statuses and Linux filesystem admission. This is a new consumer proposal, not source/API implementation or acceptance. Only the already declared file is managed. No credential discovery/readback display, new vault/root/filename, Config/reference mutation, chmod/chown repair, environment/CLI resolution/revocation, provider/authentication call, service reload, two-file transaction or producer replay. Existing manual/reference/data behavior is unchanged.

## Fixed host surfaces and request boundary
Add optional `modelCredential(request)`, IPC `manager:modelCredential`, POST `/manager-model-credential`, owner lane `model-credential`, observer action `model-credential`, private helper `model_credential_transport.py` and raw key `model_credential_raw`. Do not add a public raw helper/API or widen old DTO allowlists. One argument is required.

Confidential request union (never safe view/state/history/log data):
- `{action:"retained"}`;
- `{action:"cancel",reference:REF}`;
- `{action:"begin",connection_id:CONNECTION,boot_id:BOOT}`;
- `{action:"save",connection_id:CONNECTION,boot_id:BOOT,reference:REF,change:CHANGE}`;
- `{action:"status",connection_id:CONNECTION,boot_id:BOOT,reference:REF}`.

REF is cryptographically random lowercase64hex independent of secrets, not a content hash or cross-lane authority. Existing connection lowercase64hex and nonnil boot UUID admission remain strict. CHANGE is exactly `{action:"install"|"replace",value:TEXT}` or `{action:"remove"}`. Keep is local and dispatches nothing. No caller reference name/path/root, BINDING, INTENT, mode, secret hash or arbitrary Config is accepted. Reject unknown/duplicate fields, positional arrays, coercion, malformed scalar Unicode and arbitrary serialized payloads with static safe errors.

TEXT must encode as valid scalar UTF8, at most8192 bytes, and contain a character outside exactly U+0009..000D,0020,0085,00A0,1680,2000..200A,2028,2029,202F,205F,3000 (the current Rust whitespace-only predicate). U+FEFF alone is not blank; U+0085 alone is blank. Accepted CRLF/CR/trailing spaces/controls/NUL/non-ASCII are preserved byte-for-byte, no trimming/normalization, format guessing or appended LF. These bounds do not change resolver rules.

Confidential renderer/HTTP submit JSON cap16384 encoded bytes. Each actual prepare/apply producer JSON must independently fit16384 before any possible apply; JSON escaping and confidential binding/intent overhead matter. A text-valid8192-byte input can still be envelope-refused. Host verifies prepare envelope before prepare, then apply envelope before setting possible-dispatch; refusal sends no apply and returns not-dispatched without clipping/re-encoding/retry. UI clears input even for such refusal, with a static size/prerequisite label. Do not promise every8192-byte control-heavy string is transportable.

## Safe response (no confidential material)
Safe response is exactly `{contract_version:1,status,observation,model_credential:{state,reference,current,report,retained}}`, cap8192 UTF8 JSON bytes, with existing observation validation. `current` is null or exactly `{present:BOOLEAN}`. It is a current admitted saved-file observation, never effective authentication. No name, path, byte count, secret, secret-derived fingerprint, file metadata/mode, BINDING/INTENT, base/target/private packet or arbitrary error text is exposed. Renderer must never receive these fields even transiently in a raw report.

`report` is null or exactly `{operation,status,outcome,disk_readback_verified,runtime_activation}` reduced from the producer: operations inspect/prepare/apply/status; statuses ok/invalid-input/unavailable/unsupported/busy/conflict/failed; only producer-coherent outcomes read-only/prepared/no-change/verified/desired-file-observed/unresolved/not-dispatched/unknown. Runtime is always unverified. Disk true only on successful verified apply. Report data/report_version and raw bytes are never copied into this DTO.

States: none,ready,invalidated,unsupported,unavailable,busy,capacity,not-dispatched,no-change,verified,unknown,unresolved,desired-file-observed. Retained is at most8 exact `{reference,connection_id,boot_id,state:"unknown"|"unresolved",status_available:BOOLEAN}` records; no opaque private packet can be embedded here. TTL/status availability is control metadata, not settlement.

Ready requires actual successful inspect/read-only/current presence, a fresh ref and same observed identity. No-change requires actual successful prepare/no-change with original binding equal in EVERY private field; derive presence only after validation. Verified requires actual successful apply/verified/disk true/presence matching original intent target. Desired-file-observed requires successful status/false disk/target presence. These observed states require matching observation and request context. Unresolved requires actual successful status/unresolved/null data, null current and its own retained ref. Local cancel/failed/late/expired status uses unknown/null current/report while retaining last unresolved/unknown state; never fabricate a successful report. Busy/refusal grants no current/ready state. Invalidated/none/capacity have null current/ref; requested original ref stays bound on status/cancel refusal. Retained response is none/unconfigured/null observation/ref/current/report. All outgoing views are rechecked against generation/reference/request context before release.

A refused original status maps to unavailable/busy plus fixed sanitized report, retains original uncertainty and does not renew lifetime. Unknown may carry only a sanitized genuine failed/unknown apply report or null fallback. Missing/expired host private context cannot be replaced with a new binding: status_available:false, no I/O and unknown/unavailable diagnostic, never success/retry. A future empty retained response is not proof a renderer's previously unknown operation did not run.

## Private producer records and validation
All BINDING/INTENT/STATE/DESIRED fields in the producer contract are confidential, including config/path/metadata hashes and mode. Do not call unsalted content fingerprints non-sensitive. Host-private strict parsers only; no export to renderer modules. Inspect success must have exact schema_version1/binding, strict absent versus present record and valid lowercase hashes/mode256|384. Pin fixed Config path hash using `urn:remarkable-buddies:model-credential-config-path:v1:` plus fixed absolute Config path. Credential path is resolved only by producer; no host discovery to reconstruct it.

Begin retains only that admitted confidential binding for a ready grant. Install is allowed only absent->present0600; Replace only present->different content/same original permitted mode; Remove present->absent. Absent Remove and equal replacement are accepted as no-op only from producer prepare with exact same binding. Validate nonnil operation UUID, version1, equality of every returned intent.base field with the original binding, action coherence and original decoded UTF8 content hash/target mode before apply. A mere matching presence bit cannot establish a binding or no-op.

Save validates/clones confidential CHANGE, clears owned renderer draft/actual DOM before first await, then prepares once and applies at most once under one13000ms aggregate budget and the original ready age. Per child budget is min(12000ms, remaining operation/ready/private-context lifetime as applicable); browser/IPC wait is bounded14000ms. Recheck token/generation/deadline before possible apply. Complete no-change releases ready private context without apply. Original-expiry/mismatch/refusal before possible apply is known not-dispatched; private preparation is never mutation authority without the complete original validated result.

Seal exact original prepared report bytes and digest, validated intent/status JSON and target presence/action for original-only status BEFORE possible apply dispatch; compare their original bytes/digests before reuse. Hashes and packets remain private. Once apply may have entered the transport, lost/partial/timed/cancelled/refused malformed output is conservative unknown unless a complete valid original-bound producer not-dispatched report proves otherwise. No automatic retries, refresh, reprepare, rollback, target cleanup, second report or stage-file sweep. Actual producer determines destination-attempt versus pre-publication faults and current Store/mode custody. The host neither reimplements filesystem admission nor bypasses unsafe/missing prerequisites.

Status sends exactly original `{intent}` with no CHANGE/raw text. Producer checks original Config/path/parent location before observing only the original file; changed reference/config/root refuses rather than following a new target. Desired-present/absent/current private permissions are producer authority. Host validates status presence against the original target and same observation. Desired state may release private reconciliation material, but UI says current desired saved state observed, historical outcome unproven; no historical author/authentication or retry grant. Different state stays unresolved. Failed/cancelled/status-unavailable checks preserve the original and last observation; no implicit check or mutation on reload.

## Transport, admission and failure privacy
Fixed command is `/usr/bin/env -i HOME=/home/root PATH=/opt/bin:/usr/bin:/bin REMARKABLE_BUDDIES_CONFIG=/home/root/.config/remarkable-buddies/config.json /opt/bin/reader-buddy --model-credential-operation ` plus allowlisted inspect/prepare/apply/status. Only non-inspect adds literal ` --model-credential-input -`. No secret/name/path in argv/environment/command interpolation. Inspect has no stdin; other input is EOF-delimited strict JSON via private stdin only, never a filename fallback.

Private Node/Python request is exactly `{selector,input_base64,budget_ms,connection_id,boot_id}`, envelope cap24576 bytes; decoded JSON cap16384. Raw private response is exactly `{contract_version:1,status,observation,model_credential_raw:{status:"reported"|"unsupported"|"unavailable",stdout_base64:STRING_OR_NULL}}`, cap24576, with canonical base64 of strict UTF8 exact one-LF report capped16384 decoded bytes. Recursive duplicates/unknowns/array variants, type/version/UUID/hash/action/base/target/mode, framing and same identity are checked before safe reduction. Malformed/cyclic/BigInt payloads, library exceptions, stderr, report and parse errors never expose original values, .message, .cause, tracebacks or raw JSON in public responses/logs/telemetry.

Reuse existing hard-wired host-key/connection/boot-before-and-after checks and bounded child supervision. Both Windows/Linux Manager hosts invoke this Linux-target producer; a non-Linux/old producer refuses before target credential access, not a desktop-host feature split. No host credential-file path probe or arbitrary command is added. Raw helper result is host-private and never available through general manager-host actions, preload, broad inspection, debug methods or SafeView serialization. Fixed unsupported/unavailable labels do not guess whether reference, mode, root or provider is the cause.

HTTP retains loopback Host/origin/session-cookie/content-type/POST/no-query guards, strict bounded canonical JSON, UTF8/chunk wiping and final generation check. IPC retains exact one arg/contents/main-frame/fixed loaded UI URL guards; context-isolated sandboxed optional preload exposes only the typed capability. Safe result reader cancels incomplete streams and bounds bytes. Private body/mutable buffers are erased/references dropped per lifetime.md; immutable JS/IPC/SSH/OS copies are not guaranteed physically zeroized. No temporary secret file, browser persistence, cache, clipboard programmatic write or debug capture.
